# ChatGPT chat usage contract

[UI plan](chatgpt-chat-usage-ui-plan.md) · [Backend plan](chatgpt-chat-usage-backend-plan.md) · [Subscription provider contract](chatgpt-provider-contract.md)

Scope: ChatGPT subscription lap, comparison and experiment chat. No billing, quota conversion, compaction pricing/effort or changes to other providers/features.

- **CU-1:** Successful assistant turns carry optional `metadata.subscriptionUsage: { model: string; inputTokens: number; cachedInputTokens: number; outputTokens: number }[]`, in upstream completion order. Counts are nonnegative integers, cached input is a subset of input, and output includes reasoning. Each item describes one completed provider request, not a whole conversation. Persist and replay the metadata with the assistant turn. Aborted/failed turns or turns with incomplete attribution have no estimate. Old history has no such field.
- **CU-2:** `GET /api/ai-chat-pricing` uses existing API authorization and returns `200 { fetchedAt: number | null; models: Record<string, { input: number; cachedInput: number; output: number; longContext?: { threshold: number; input: number; cachedInput: number; output: number } }> }`. Timestamp is Unix ms of the last successful validation. Rates are USD per million tokens at Standard API rates. Data is public, fetched without account credentials or chat data. At startup, fetch in the background only if no valid on-disk snapshot exists. After six hours, refresh on demand. Share concurrent fetches, throttle retries, and serve the last valid snapshot if refresh fails. An outage without a valid snapshot returns null and an empty object.
- **CU-3:** Footer computes the estimate for the latest completed subscription turn (all its upstream requests). Match exact response model, select long-context rates independently per request based on input length, and charge cached input once at its rate. Example: 1,000 input, 500 cached, 100 output at $2/$0.10/$10 per million yields $0.00205. Label as estimated API cost, not a subscription charge, and expose the price fetch date. If any rate or usage is missing, omit the estimate and retain token counts. Historical usage is never repriced using a different model selected in settings.
- **CU-4:** Existing settings API adds `chatSubscriptionReasoningLevel: OpenAiReasoningLevel | null`, default null (model default). Existing enum remains authoritative for parsing; a saved value unsupported by the chat model is treated as null by both layers. Use the same documented model capability lookup on both sides. Only subscription Chat inference writes `reasoning: { effort: … }`, and only for a supported explicit level. Changing model does not coerce effort to another explicit level. Other settings, providers and inference are unchanged.

## End-to-end evidence

Reuse seeded Playwright chat and Settings paths. Run real RaceIQ client, routes, stream bridge, memory, and settings persistence against isolated data; control only upstream inference/catalog responses. Main session records commands and actual results. A fixture that intercepts RaceIQ UI/API alone does not count.

- **CU-E1 (CU-1/2/3):** Open chat with a subscription model. Complete a two-request tool turn with cached tokens and one long-context request. Check request-level math and fetch date in the footer. Reload and switch the configured model; the historical result retains its original model attribution. Incomplete/aborted requests and missing or unknown model rates retain token counts without a price.
- **CU-E2 (CU-2/3):** Start the backend with an empty data directory; observe one catalog fetch before any chat request and a snapshot written on success. Restart with saved rates; boot alone does not contact the catalog, even if the snapshot is expired. Open multiple seeded chats; reuse rates before six hours, then share one refresh at expiry. Fail refresh and confirm original rates/date and bounded retry. Recover with new rates and confirm refresh. Cold failure must not block chat.
- **CU-E3 (CU-4):** Open AI Chat settings, select a supported model and explicit effort, save and reload. Send a turn and inspect upstream request. Switch to unsupported model, then choose model default on a supported model; neither sends effort. Exercise lap, Compare, and experiment chat with the shared binding; confirm OpenAI API-key setting and non-chat subscription requests are unchanged.

## Verification results

The macOS loopback pilot served the built client and real RaceIQ routes, settings, and chat memory. An isolated account fixture supplied a fake grant; a test-only transport intercepted OpenAI and pricing requests. No real subscription inference or account storage was exercised.

- **CU-E1:** Chromium showed `$1.089654` for a two-request experiment tool turn and memory retained both request records. A `$1.087604` long-context result survived reload and a model switch. An unpriced model showed tokens without an estimate. Incomplete and cancelled turns persisted no pricing attribution.
- **CU-E2:** Browser and real `/api/ai-chat-pricing` checks passed with a controlled clock: cold outage did not block chat, warm calls reused one fetch, an expired snapshot survived a failed refresh, failures were throttled, and recovery updated the amount and fetch timestamp.
- **CU-E3:** Chat settings saved and reloaded High. Experiment, lap, and Compare requests forwarded High. Model default and a model without capability data omitted `reasoning`; OpenAI settings remained independent. The structured Analysis adapter regression verified that non-chat subscription requests still omit `reasoning`.
- Seeded `streamed-setup.spec.ts` passed against the built pilot. `bun run typecheck`, the focused pricing/provider and changelog tests, and `bun run i18n:check-keys` passed.
