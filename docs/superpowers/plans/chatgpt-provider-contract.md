# ChatGPT subscription provider contract

Status: approved for implementation. Distribution eligibility and live compatibility remain unverified; release is not approved.

[UI plan](chatgpt-provider-ui-plan.md) · [Backend plan](chatgpt-provider-backend-plan.md) · [ADR](../../adr/0016-chatgpt-subscription-provider.md)

## Scope

Add **ChatGPT subscription** (`chatgpt-subscription`) as a peer of OpenAI API key in every existing AI provider selector. Connect once, then select a provider/model independently for Analysis, Chat, Auto-tune, and Driver Profile. Existing analysis/chat defaults, model preferences, and credentials stay unchanged. Chat also drives compaction; a blank Auto-tune provider retains its Analysis inheritance. Cover all production inference entry points, including lap and comparison analysis, lap/comparison/experiment chat (car and driver focus), consults, regeneration, compaction, LLM Auto-tune, and manual and enabled background Driver Profile. Deterministic telemetry and the rules-based tune engine do not invoke this provider.

Use the documented [Sign in with ChatGPT local OSS flow](https://developers.openai.com/siwc/token-sharing-open-source) and [public Responses API](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference). No ACP, Codex process, OMP credential import, private ChatGPT endpoints, or API-key fallback. Confirm eligibility for the actual RaceIQ distribution before live integration; AGPL source alone doesn't establish eligibility for a paid or remote product. Use OpenAI's documented inquiry/approval route if needed. Target the packaged local Windows desktop app first; keep the provider unavailable in builds without an eligible local configuration and protected storage. Nonlocal callers cannot use local credentials. Preview compatibility across **all** required features is a release gate, not permission to ship a chat-only subset. Plan limits apply; OpenAI can use credits if the account owner enables that in ChatGPT. RaceIQ never switches to API billing on its own.

## Provider, models and settings

- Extend authoritative [`AI_FEATURES` and `AiProvider`](../../../server/ai/ai-features.ts), provider capabilities, existing `/api/settings` provider fields (`aiProvider`, `chatProvider`, `autoTuneProvider`, `driverProfileProvider`) and paired string model fields. Example: `PUT /api/settings { "chatProvider": "chatgpt-subscription", "chatModel": "returned-model-slug" }`; response remains existing settings DTO. Changing into this provider or changing its model requires an active authorized account and a currently offered model. Reject invalid changes atomically. Unrelated saves work with stale/disconnected choices. Preserve legacy `codex` cleanup; no opt-in migration and no credential/account IDs in settings. An explicitly selected subscription provider never borrows a different provider's model, key, or endpoint. If Auto-tune inherits a subscription provider from Analysis, use the Analysis pair together. Compaction uses the Chat pair.
- `GET /api/ai-providers` adds `{ id: "chatgpt-subscription", name: "ChatGPT subscription", ready: boolean }` when the local runtime is eligible. `ready` means an active usable grant, not available quota. With no eligible runtime, omit from new choices; if already selected, show it as unavailable with a control to switch away. Do not change existing provider discovery or `/api/ai-key` behavior.
- Existing `GET /api/ai-models?providers=chatgpt-subscription&refresh=1` returns the usual provider map plus `"chatgpt-subscription": Model[]` and `_errors["chatgpt-subscription"]: string | null` when requested/selected and available locally. `Model` has required `id: string`, `name: string`, `features: ("analysis" | "chat" | "autoTune" | "driverProfile")[]`, and `supportsImages: boolean`. Example: `{ "id":"returned-model-slug", "name":"Model display name", "features":["analysis","chat"], "supportsImages":false }`. Fetch via public `/v1/models`; keep `visibility: "list"` and upstream order; map `slug` and `display_name`. Derive `features` from one verified backend capability table shared by discovery and inference validation; `chat` requires chat, tools and compaction. Omit catalog models verified for no RaceIQ feature. Filter each picker by its feature. An empty list with null error means no verified choices, not a transport failure. Invalidate the cache on account switch, sign-out or forced refresh. Preserve saved selections on failures; require explicit reselection if the model is no longer offered for that feature. Never invent a default or silently discard images in a submitted conversation. Show vision only for models with `supportsImages: true`. Use model defaults for reasoning on this provider; don't show or send the API-key provider's reasoning or output-budget settings.

## Account API

New protected routes under `/api/auth/chatgpt-subscription`. Use existing RaceIQ authorization and enforce trusted local transport, canonical Host/Origin/CSRF on mutations, and no untrusted forwarded identity. Settings validation, catalog and *all* user-triggered provider requests share the local invocation guard. Only already-enabled local Driver Profile scheduling can invoke without a browser request; do not enable it on connect. Use `Cache-Control: no-store` on account and scoped discovery responses. The temporary browser callback is separate: bind only `127.0.0.1`, `/auth/callback`; validate the single pending OAuth attempt instead of depending on RaceIQ cookies.

| Operation | Request | Success |
| --- | --- | --- |
| `GET /` | None | `200 State` |
| `POST /connect` | `{ accountId: string \| null }`; null adds a registration, saved ID reauthorizes it | `201 { attemptId: string, authorizationUrl: string }`. One pending attempt per installation. |
| `DELETE /connect/:attemptId` | Matching opaque ID | `204`, idempotent; stale IDs do not cancel other attempts. |
| `PUT /active` | `{ accountId: string }` | `200 State`. Changes active account only if authorized; does not change provider assignments or model IDs. |
| `DELETE /accounts/:accountId/session` | Saved opaque ID | `200 { state: State, revocation: "confirmed" \| "unconfirmed" \| "not_needed" }`. Clear local tokens and active reference if it matches. Keep registration for returning sign-in. Never activate another account implicitly. |

`State` contains required `availability: "available" | "unavailable"`, `activeAccountId: string | null`, `accounts: { id: string, label: string, session: "connected" | "signed_out" | "reauth_required" }[]`, and `attempt: null | { id: string, accountId: string | null, status: "pending" | "succeeded" | "cancelled" | "failed", error: ErrorCode | null }`. Account IDs are opaque; labels distinguish equal emails. Initial successful connect activates the account only when there is no active one; otherwise switching is explicit. Pending attempts expire after five minutes; retain the latest outcome until a new attempt. On success expose the saved account ID. An unavailable runtime returns empty accounts, null active ID and null attempt, without reading protected records. Example fresh state: `{ "availability":"available", "activeAccountId":null, "accounts":[], "attempt":null }`.

`ErrorCode` for new auth/provider errors: `invalid_request` (400), `forbidden` (403), `attempt_in_progress`, `reauth_required`, `plan_unavailable`, `model_unavailable` (409), `usage_limit` (429), `unavailable`, `upstream_unavailable` (503), `storage_failed` (500). OAuth attempt outcomes additionally use `consent_denied`, `oauth_invalid`, `oauth_timeout`. New JSON failures use `{ code, error }`; extend existing feature error envelopes additively where they already use a different shape. After streaming starts, use each existing stream error channel with a sanitized message; never report success from a terminal provider failure. Existing validation and non-subscription errors remain unchanged. No raw response bodies, credentials, authorization URLs or OAuth query parameters in logs, settings, browser storage or support traces. Authorization URL is returned solely for the user's sign-in action; omit optional token hints from the launch URL.

Follow upstream [registration](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) and [session lifecycle](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions). Validate OAuth state, PKCE, JWKS signature, issuer/audience/nonce/identity and granted scope before persistence. Preserve active account and settings on invalid callback, timeout, cancelled replacement, or failed storage. Atomically rotate credentials; serialize refresh across concurrent turns and prevent late results from restoring revoked sessions. Sign-out aborts in-flight work for that account and stops new calls before revocation; show unconfirmed remote revocation and block use on local storage failure. New turns use the newly selected account; an in-flight operation may never switch credentials to another account or another provider. Missing, stale and revoked configuration fail closed; preserve existing saved results/history and allow explicit recovery.

## Inference and compatibility

[`/v1/responses` preview rules](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) are authoritative: OAuth bearer, fixed public endpoint, `stream: true`, `store: false`, explicit history, no unsupported params or prior response references, instructions/developer role, documented function namespaces or `additional_tools`. This applies to operations presented as non-streaming in RaceIQ too: aggregate validated events server-side, return existing response types, and accept success only after `response.completed`. Verify support for structured schema/output and app-controlled tool continuation live. Preserve tool names, args, results, authorization, user confirmation and output validation; any transformation between provider wire names and RaceIQ tool IDs must round-trip without weakening existing tool guards. Nested analysis tools use their own configured feature; preserve explicit user configuration and confirmations, never treat a failed subscription request as permission to call another provider. Existing durable state changes keep their current contracts: failures never save successful analyses, invalid tune changes, profiles or compaction summaries; confirmed tool side effects must not repeat on retries. On cancellation, stop transport and preserve the existing failure/abort contract; never mark a partial turn complete. Do not add a weak unvalidated-text fallback if a structured operation is incompatible.

## Verification matrix

Use seeded Playwright with real application and routes, DB, Mastra, auth callback listener and bundled storage path. Use isolated settings, DB, OS user/credential namespace, authorized browser fixtures, and a controlled upstream at the OpenAI boundary only. Harness endpoint injection must not be present in shipping builds. Cover success and failure through actual application entry points; observe both workflow state and outbound provider identity. Main session owns end-to-end verification. Live evidence from the packaged, eligible Windows app is separate and required for release.

| Acceptance criterion | Required scenario: setup → action → result |
| --- | --- |
| **CG-1** Connect, discover and select provider in all four settings sections. | **CG-E1:** Old settings and no OpenAI key. Sign in through actual loopback callback, choose four account-returned models independently; reload and restart. Verify choices/catalog/readiness survive. Switch account and check ordering, empty catalog, model disappearance, unsupported operation, resave and unchanged unrelated settings. UI-only: keyboard connect/cancel/select/save and retry. **CG-L1:** Real browser sign-in, account model discovery, restart and refresh on packaged Windows. |
| **CG-2** Trusted local auth, protected storage and lifecycle. | **CG-E2:** Exercise invalid state/token/identity/scope, denied consent, cancel, timeout, duplicate callback/connect and distinct same-email registrations. Start parallel work with expired token; see one refresh, no account substitution. Sign out during a turn, exercise revocation and storage failures; no credential use once signed out. Try LAN invocation, foreign Origin, forged forwarded headers and bad Host; see no outbound token/inference. Inspect browser storage, settings, logs and process boundary for secrets; verify protected persistence and no plaintext temp files. |
| **CG-3** Chat and tools retain behavior. | **CG-E3:** Seed a lap, comparable lap and experiment. Send/stop/reload lap and compare chat; switch experiment focus and verify car and driver tools remain separated, including rejection without confirmation and exactly-once confirmed write. Exercise follow-up, authorised consult, regeneration and image capability checks. Compact through `/api/chats/:threadId/compact`; verify summary/history and successful next turn. Verify outgoing namespaced tools, instructions, explicit history and tool continuation. |
| **CG-4** Structured and scheduled features remain valid. | **CG-E4:** Generate lap analysis and comparison/inputs analysis and verify persisted schema/provenance. Run LLM Auto-tune at `POST /api/tunes/auto` with explicit provider and inherited Analysis pair; check validated intent and applied preview. Run a manual profile at `POST /api/drivers/profile/runs` and the real enabled background scheduler on fresh eligible laps; assert schema and completion. Disable the scheduler and observe no call. Verify deterministic rules run without model traffic. |
| **CG-5** Fail closed with actionable recovery and no billing fallback. | **CG-E5:** Drive catalog outage, upstream HTTP and SSE plan/quota errors, revoked grant, malformed/invalid structured output, incomplete/aborted stream, failed compaction and failed scheduler work. Verify existing failure states, no success persistence/duplicate tool writes, no fallback key call, retry or reconnect, then explicit switch back to API-key provider. Verify pre-existing provider payloads/models and persisted results are unchanged. |
| **CG-6** The public preview supports the complete provider. | **CG-L2:** In the real packaged app and eligible account, exercise live representatives of **each** CG-E3/CG-E4 entry point: streamed chat and grounded tool continuations, compaction, structured lap/comparison analysis, tune and profile; include both experiment focus modes and a scheduled run. Record model and completed results. **CG-L3:** Confirm cancellation and account switch/sign-out behavior against live service; inject adverse limits only in CG-E2/E5, not by exhausting a real account. |

After integration, run CG-E1–E5, CG-L1–L3 and `bun run typecheck` and record commands/scenarios, observed results and blockers. If the packaged app, eligible OpenAI account, protected storage or required live capability is unavailable, mark affected criteria unverified and block release. Do not drop unsupported features without scope approval.
