## Credential and authorization path

Use a dedicated auth service and temporary loopback callback. Keep PKCE/state/nonce in memory; follow upstream metadata, token validation and lifecycle documents linked from the contract. Bind requests to the active local user/install, not Host alone. Verify the desktop and development proxy access identity against `apps/backend/src/routes/index.ts` (`httpAccess.authorize`); define the trusted-local proof at the real HTTP ingress, never trust client-supplied forwarding headers. Propagate proof before provider resolution to normal and nested requests, and distinguish the already-opted-in internal profile scheduler. Serialize token refresh and session changes, including cross-process access if multiple processes can use the same data directory. Fail closed after storage errors or revocation. Model discovery uses the same account fetch path and bounded cache, but does not expose JWT claims, keys or billing state. Rate-limit auth starts with one pending attempt and a five-minute expiry; dispose of listeners on cancel, expiry, completion and app shutdown.

On Windows use user-bound DPAPI protection for an atomic encrypted credential record, with a minimal packaged helper or platform binding that transfers plaintext only through private process pipes. Store only protected bytes on disk; scope to the Windows user and isolated data root. Do not pass OAuth secrets through `server/runtime/platform/keystore.ts` as written: the Windows helper uses process arguments and plaintext temp reads, which are unacceptable here; a full token set also can't be assumed to fit one Credential Manager item. Verify errors, support, packaged availability and restart behavior before enabling. No plaintext or silent in-memory fallback in the shipping app. Persist the opaque host ID separately; make sign-out clear the local session even when remote revocation is unconfirmed; storage deletion failure blocks inference and reports failure. Use existing application support-log redaction boundaries; ensure secret-bearing subprocess output/input and HTTP auth never reach traces.

## Provider adapter and cutover

1. Extend the provider enum using `chatgpt-subscription`, keeping legacy `codex` cleanup. Add per-operation model eligibility, discovery and deliberate settings validation; preserve legacy settings snapshots and other providers' selections. Validate subscription model/provider pairs as pairs, especially Auto-tune inheritance. Do not synthesize a model or read `OPENAI_API_KEY` when subscription is selected.
2. Start at `getMastraModelId`/`bindMastraModel` and `resolveAi`, using the existing `RESOLVED_AI_MODEL_CONTEXT_KEY` path for request-scoped binding. Reuse the AI SDK Responses interface where compatible. Normalize only the subscription wire payload at the provider edge (fixed endpoint and bearer, stream for every operation, stateless history conversion, unaccepted params, tool namespace encoding/decoding, terminal error and cancellation). If static `generate` can't produce the required wire stream, implement the provider's generate operation by consuming and validating its stream. Preserve `AiResult`, schema and usage contracts; do not route through the API-key adapter's raw structured path. If SDK round-tripping fails, implement only the necessary model interface behavior and revalidate live; do not change global OpenAI middleware or process env. No silent relaxed schema or tool continuation conversion.
3. Audit actual production entry points before closing BE-3. Paths below are verified starting points, not permission to omit another consumer of `AI_FEATURES`:

   | Feature | Existing entry point and required integration |
   | --- | --- |
   | Lap and comparison analysis / nested lap analyst | `apps/backend/src/ai/generate-lap-analysis.ts`, `consult-lap-analyst.ts`; `apps/backend/src/routes/laps/comparison-routes.ts` (`inputs-analyse`); existing structured schema/provenance gates. |
   | Lap, comparison, and experiment chat | `apps/backend/src/routes/laps/chat-routes.ts`, `comparison-routes.ts`, `apps/backend/src/routes/tune-chat-routes.ts`; replace subscription-only assumptions about provider env/defaults with bound model and verified capability gating. Preserve Mastra memory, experiment focus, tool scopes and approvals. |
   | Regeneration and compaction | `apps/backend/src/routes/chats-routes.ts`; dispatch regeneration into existing chat path and inject shared provider path into `server/ai/compact-thread.ts`'s direct model construction. Preserve generations and summary validation on failure. |
   | LLM Auto-tune | `apps/backend/src/routes/tunes/auto-routes.ts`, `server/ai/tune-intent.ts` (`runTuneIntentProvider` direct switch); prevent default Gemini fallthrough, preserve rules mode, generated intent validation and atomic preview/apply. |
   | Driver Profile | `apps/backend/src/routes/driver-routes.ts`, `apps/backend/src/driver-profile/runner.ts` and registered background trigger; replace subscription-only credential/default assumptions; report blocked/revoked runs without changing opt-in or last good profile. |

4. Preserve specialized call settings when allowed; omit specifically unsupported subscription fields rather than silently changing the behavior of API-key providers. Regression-check auth for all old providers. Keep terminal failure distinct from success, stop outbound work on abort/sign-out, and preserve existing idempotence for confirmed mutations.
