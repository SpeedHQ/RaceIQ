# Catalogue package impact: UI plan

Status: proposed. [Shared contract](catalogue-package-impact-contract.md) · [Backend plan](catalogue-package-impact-backend-plan.md) · [ADR 0017](../../adr/0017-catalogue-package-impact.md)

## UI-01: Make catalogue UI ownership visible to Turbo

**Owner and scope.** UI implementation owner: `packages/{cars,tracks}-catalogue/ui/**`, `client/src/features/{cars,tracks}-catalogue-host.tsx`, and the catalogue route entry files in `client/src/routes/$gameid/`. Coordinate any shared-source move and all manifest/Turbo changes with the integration owner before editing. No Home/Experiments moves, router redesign, backend changes or presentation changes. Start after contract approval; no backend implementation dependency.

1. Start from the `CarsCatalogueHostProvider` and `TracksCatalogueHostProvider` adapters, `client/src/routes/__root.tsx` and the `cars.tsx` and `tracks*.tsx` route entries under `client/src/routes/$gameid/`. Confirm any additional entry routes before declaring ownership closed. Keep routing, Paraglide, app auth/RPC, game context and settings in the app; keep their relevant files in the shared impact boundary. A generated route tree or a compiled bundle alone is not a dependency on every leaf page.
2. Keep page-specific components in the existing feature packages. Use the host adapters as the short, explicit app boundary. Check imports from both adapters, including assets, CSS and locale sources. Cars uses model assets, search and tables. Tracks also injects track geometry rendering, setup and guide panels, tune/lap hooks and detail navigation. Shared theme, UI primitives and app-provided hooks still select their consumers. Do not move them merely to avoid writing a bounded shared input. If a shared folder contains unrelated feature code and still defeats the acceptance checks, propose the smallest coherent extraction and list its callers before widening the write scope.
3. Give integration the package dependencies and positive app-seam inputs for `e2e:impact`. Replace blanket app UI inputs for these two tasks with this boundary and remove the Home/Experiments exclusions. Do not narrow inputs for other Playwright projects. Check that any new host import is covered by an existing workspace or shared input boundary before accepting the cutover; keep conservative coverage if it is not.

**Acceptance and handoff.** [CAT-1/E1](catalogue-package-impact-contract.md#acceptance-and-end-to-end-evidence) covers Home/Experiments edits and additions; CAT-2/E2 covers owned UI and shared controls; CAT-4/E4 covers root wiring, deletion/move and seed; CAT-5/E5 covers fallback and manual full; CAT-6/E6 covers the compiled app. Extend the existing selector fixture rather than invent a workflow. Report changed paths, app seams and package edges to integration. Integration runs the shared hosted and compiled-app scenarios after both layers land and records observed results.
