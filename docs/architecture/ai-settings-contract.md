# AI settings contract

This extends the shared AI contract in [the desktop goal](../project-status/macos-desktop.md).

## Editable analysis instructions

- Settings expose `lapAnalysisInstructions` and `compareAnalysisInstructions`.
  Each is plain text, at most 12,000 characters; `null` restores the shipped
  default. Empty text deliberately removes this optional guidance.
- The editor displays the effective instructions, supports explicit Save and
  Reset, and preserves unsaved edits on failed requests. Both providers and
  games use the same saved preferences. No executable templates or interpolation.
- Instructions customize coaching focus and presentation. Backend-owned JSON
  schemas, valid corner labels, units, evidence rules and tool permissions remain
  authoritative. Telemetry and setup context are always generated by RaceIQ.
- Persist with the existing authenticated settings API. Never log editor drafts.
- Analysis cache identity includes effective instructions, provider, model,
  reasoning setting, response budget, units, language and prompt revision.
  Comparison identity also includes displayed lap order; reversing A and B
  requires new analysis, including when fetched by the comparison chat tool.
  A changed identity misses the cache without deleting previous results.
  Existing rows without identity remain stored but require regeneration.

## Codex discovery

- Codex uses its managed ChatGPT account, without an API-key field.
- Backend discovers only trusted configured/default executable locations.
  Browser requests cannot provide commands, paths or argv.
- Discovery may inspect runtime version, account type and model metadata, never
  submit telemetry, run an inference turn or change global configuration.
- Report missing CLI, unsupported runtime, sign-in required and ready distinctly.
  Model catalog membership is not proof of entitlement; generation errors remain
  authoritative. Only models with a verified isolation profile are selectable.
- Capability-specific selection must reflect implemented flows. Chat and setup
  remain unavailable until their history/tool bridges are implemented.
- Codex lap analysis defaults to `gpt-6-luna` with `medium` reasoning when
  selecting Codex. Previously saved model choices remain unchanged; the model
  picker lists only discovered models with a verified isolation profile.
- Backend plan: verify Luna's isolated runtime and account access, expose Luna
  alongside other verified models, and send explicit medium reasoning for Luna. UI plan:
  preselect Luna when switching to Codex while retaining the existing model
  picker. Both plans depend on these discovery and isolation guarantees.
- A failed Codex turn classified by app-server as `usageLimitExceeded` or
  `rateLimitExceeded` reaches lap and comparison analysis with distinct,
  actionable messages. Never infer a reset time, expose raw provider errors,
  retry automatically, or fall back to a billable provider. Other failures
  remain distinct from usage limits; failed analyses are not cached as results.

## Response budgets

Lap and comparison each persist an independent requested output ceiling,
between 512 and 65,536 tokens, defaulting to 32,768 for experiments. This is
a request, not a model capability guarantee: hosted providers may reject values
above their limits. Codex 0.164.0 exposes no supported output-cap control;
its requested setting is recorded for comparison but effective cap stays unknown.
Changing either ceiling invalidates only the corresponding analysis cache.

Backend plan, depending on this contract: validate and persist both settings;
pass each value to the direct and Mastra generation paths and cache identity;
preserve unsupported Codex diagnostics. Acceptance: settings validation,
provider requests and cache invalidation tests cover both features.

UI plan, depending on this contract: expose independent validated controls in
AI Analysis settings, preserve drafts on save failure, and explain that model
limits vary and Codex cannot apply this setting. Acceptance: saved values persist
through reload and the Codex limitation is visible without an API key.

## Codex chat and engineer bridge

- The isolated tool-capable profile is limited to the tested CLI 0.164.0 and
  `gpt-6-luna`; unknown metadata fails closed before telemetry is sent. It must
  expose only explicitly registered RaceIQ tools and reject built-in execution,
  collaboration, goal, user-input, clock, patch, image, network and MCP tools.
- Lap and comparison chat retain the existing client stream and canonical
  conversation history. Tool requests are turn-scoped, argument-validated,
  bounded and read-only. Failure, cancellation and reconnect preserve history.
- Experiment roles use the same profile only after durable idempotency and the
  existing authorization and confirmation rules protect all writes. Engineer
  and coach tools remain mutually exclusive. A mock call is not proof that a real
  model can invoke the same tool or that an experiment mutation is safe.
- Backend plan: implement and test the version-pinned profile and tool bridge;
  connect read-only chat, persistence and streaming; then implement domain-safe
  experiment writes. Acceptance requires mock negative and duplicate-call tests,
  authenticated tool calls, resumed history and one authorized setup change.
- UI plan: enable Codex only for operations supported by the backend, with
  Luna model selection and existing chat, retry and confirmation controls.
  Acceptance requires translated settings, streamed chat and history after
  restart, cancellation and both experiment roles in browser and native app.
- Driver Profile uses its own Codex provider/model selection and the existing
  opt-in for background runs. The backend sends only its computed fingerprint
  through isolated structured generation, validates the existing summary
  schema, preserves stale-pool protection and records reported usage; Codex's
  requested output ceiling is disclosed as unsupported. The UI uses discovered
  Codex models without an API key, preserves all other providers, and reflects
  the same generation and budget contract. Both plans require focused success,
  failure and persistence tests before the selector is enabled.

## Backend plan

Depends on this contract. Add validated settings and shared defaults, inject the
effective instructions into lap and comparison generation, persist generation
identity, and expose bounded Codex discovery. Acceptance: settings round-trip,
reset, changed-prompt cache misses, unchanged cache hits, schema preservation,
discovery errors and cleanup have focused tests.

## UI plan

Depends on the same contract and typed settings/discovery endpoints. Compose
existing settings controls with translated textareas, Save/Reset and status.
Add Codex to supported feature selectors without requiring an API key.
Acceptance: edit/save/reopen/reset, failed-save draft retention, Codex readiness
and model selection verified in browser; installed native verification remains
a separate gate.
