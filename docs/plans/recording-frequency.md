# Selectable recording frequency — issue #447

ADR: [Recording ceilings and retention](../adr/0011-recording-frequency-and-retention.md).
Implementation ownership: [UI plan](recording-frequency-ui-plan.md), [backend plan](recording-frequency-backend-plan.md); both follow [shared contract](recording-frequency-contract.md).

## Context
Implement https://github.com/SpeedHQ/RaceIQ/issues/447: setup offers exactly 50, 60, 70, 80, 90, and 100 Hz; native capture follows the selected rate; lower rates reduce recording size and capture-processing work over equal durations. Live UDP capture is unaffected. User explicitly selected **100 Hz** as the default for new installations and old settings without this field. Frequencies are capture ceilings constrained by source availability, not promises to manufacture samples: iRacing publishes approximately 60 Hz.

Also add manual downsampling of all eligible existing recordings or recordings older than a selected age, and opt-in scheduled downsampling beside automatic deletion. User confirmed historical targets 50/60/70/80/90/100 Hz, ages 30/90/180/365 days, inclusion of UDP-origin history without changing live UDP rates, favorite protection, and exclusion of MoTeC and unsupported/unreliably timed sources. When both automatic policies are enabled, deletion age must be strictly greater than downsample age; equality and reversed ordering are invalid.

Use Effect for scheduled recording maintenance and server-owned archival jobs, with compatible repository tooling and explicit contributor documentation. User approved runtime dependencies, diagnostics/compiler setup and bounded updates to the existing instruction file; do not create editor-specific files.

### 3. Sample before expensive native frame work
- Create `server/games/shared/native-capture-rate-limiter.ts`, exporting `class NativeCaptureRateLimiter` with `shouldCapture(nowMs: number, frequencyHz: RecordingFrequencyHz): boolean` and `reset(): void`. Add its explicit backend-core package export. Search found no existing native cadence limiter. Keep only primitive per-instance state; no allocations per tick.
- Use `performance.now()` for admission, not wall-clock or game elapsed time. First call after reset or frequency change admits immediately and establishes a phase deadline `nowMs + 1000 / frequencyHz`. Before deadline, reject. At/after deadline, admit one current frame and advance by enough whole periods to put the deadline strictly after `nowMs`, anchored to the previous deadline; use a small numeric comparison tolerance to handle floating-point boundaries. Never set the deadline to `nowMs + period` on every ordinary admitted frame: that would turn 50 Hz sampling of 60 Hz input into approximately 30 Hz. After a stall, admit only one current frame, never catch up with queued duplicates. Reset on source/assembler start and stop. Detect frequency changes in each limiter and rephase there, so live saves need no observer registry.
- `server/games/kunos/triplet-assembler.ts`: give each assembler one limiter. Keep its existing 100 Hz polling timer, but gate at the beginning of each callback before `getLatestBuffers()`, triplet allocation and enqueue. Both ACC and AC Evo already use this assembler, so this covers normal capture and `--record` dumps without changing adapter constructors or status gates. Preserve FIFO drain and selected-frame `Date.now()` timestamp. Adjust fixed-100-Hz comments/log wording to distinguish polling from selected capture. Do not lower the buffered reader's native 300 Hz physics / 60 Hz graphics acquisition timers: retaining fresh snapshots avoids introducing additional sampling loss; lower capture still reduces assembly, parsing and persistence work.
- `packages/game-lmu/src/source.ts`: give the source one limiter; in the running timer callback, gate before calling `pollOnce()`. Thus rejected ticks do not read/copy shared memory, encode/decode, queue, dispatch, or write. Keep the existing polling timer option, changed-snapshot deduplication and identity handling. `pollOnce()` remains an explicit one-shot capture operation for existing consumers/tests; rate control belongs to the running loop.
- `packages/game-iracing/src/source.ts`: retain 240 Hz SDK polling and unchanged-tick deduplication to avoid missing source updates. In `pollOnce()`, after a non-null snapshot but before session parsing/cache mutation, encoding and queueing, gate only when the source is running. Rejected snapshots must not advance identity/encoder state. This caps recording and downstream processing while preserving SDK acquisition freshness. Explicit `pollOnce()` calls on an unstarted source remain one-shot operations. Keep original capture timestamps for admitted frames, high-resolution-timer ownership, error handling and drain-before-finalization behavior.
- Apply to ordinary native capture as well as dump mode: ordinary capture also produces session recordings downstream. Do not merely discard writes after parsing. Source ceilings remain valid: 70–100 Hz iRacing selections cannot increase its approximately 60 Hz source rate; do not duplicate samples. Empty/disconnected sources remain governed by existing detection/retry logic, with no generated frames or catch-up backlog.

### 5. Persist and validate the retention lifecycle
- Extend `AppSettingsSchema`, client `DisplaySettings` and matching defaults with `sessionDownsampleEnabled: boolean = false`, `sessionDownsampleAgeDays: 30 | 90 | 180 | 365 = 30`, and `sessionDownsampleFrequencyHz: RecordingFrequencyHz = 50`. Keep existing deletion defaults: disabled, 90 days. Archival target is independent from live `recordingFrequencyHz`; archival changes must never change any live capture rate.
- Export `isRecordingRetentionPolicyValid(settings: { sessionDownsampleEnabled: boolean; sessionDownsampleAgeDays: number; sessionCleanupEnabled: boolean; sessionCleanupAgeDays: number }): boolean` from the new shared frequency-contract module. Return false exactly when both switches are enabled and `sessionCleanupAgeDays <= sessionDownsampleAgeDays`. Keep the object Zod schema unrefined so `PartialSettingsSchema = AppSettingsSchema.partial()` keeps working; cross-field validation operates on complete merged settings, never the partial body alone.
- In PUT `/api/settings`, validate `merged` before socket/runtime side effects or persistence. Reject conflicts with HTTP 400 `{ code: "INVALID_RETENTION_POLICY", error: "Automatic deletion must be scheduled after automatic downsampling." }`. No automatic age adjustment or saving half a policy. `saveSettings` also refuses an invalid complete policy. If loading an externally edited settings file finds conflicting enabled policies, return settings with only `sessionCleanupEnabled` disabled, log the conflict, and preserve all other values; this suppresses destructive work rather than losing unrelated settings. Revalidate the scheduler snapshot defensively before any retention operation.
- Add nullable `sessions.downsampledFrequencyHz`, SQL column `downsampled_frequency_hz INTEGER`, in `server/db/schema.ts` and the next migration in `server/db/migrations.ts` following existing ordered SQL migrations. Null means no archival cap has been established. A value <= requested target means never upsample or reprocess that capture at a higher/equal target. Set the cap for every session sharing a rewritten file atomically; this prevents five-minute maintenance from repeatedly resampling the same history. A changed lower target remains actionable. This metadata is independent from capture-format version.

### 7. Rewrite selected frames without breaking replay or lap indexes
- Create `packages/capture-formats/src/session/downsample.ts` for format-level streaming inspection and two-pass rewriting. Keep DB eligibility, atomic publication and job ownership in `server/session-capture/session-downsample.ts`. The recording package must not import backend-core: inject a strict record-iterator factory backed by `iterateSessionCaptureRecordsFromSource(source, { strict: true })` and a fresh per-pass telemetry-parser factory. Reuse canonical framing encoders and `SparseCaptureEncoder`. Retain bounded streaming buffers and O(number of laps/segments) index plans, not full decompressed captures or an object per source frame.
- Pass one validates all records, maps every non-null lap start offset to its old frame ordinal, computes its old half-open ordinal window `[start, start + rawFrameCount)`, and finds first/last parseable telemetry records per lap and segment. Validate offsets/counts before writing. **`rawFrameCount` counts all frame records, including ancillary frames, not only parsed telemetry** (`parseRawLapFramesFromSource` increments for every frame). Null indexes stay null. Reject a malformed indexed window or a window with no replayable telemetry; preserve original files and indexes.
- Timing uses one consistent clock per segment/telemetry stream, chosen by preflight: use persisted `frameTimeMs` only if all samples in that stream carry it. Otherwise canonical UDP FM uses raw `TimestampMS` (`readUInt32LE(4)`), unwrapping a backwards jump larger than 2^31 by adding 2^32; F1 uses `parseF1Header(frame).sessionTime * 1000`, scoped by `sessionUID`. Never mix UTC and simulator time within one stream. For native captures without complete recorder timestamps, or nonfinite/ambiguous clocks, report `unreliable-time` rather than use replay wall-clock or ordinal guesses. Other timestamp regressions rephase sampling; F1 session UID and segment boundaries also reset the phase. Preserve the original timestamp prefix, including absence; never synthesize UTC from simulator time.
- Reuse the phase-preserving admission arithmetic from step 3, driven by historical time rather than `performance.now()`. Preserve each segment's first/last telemetry frames and each indexed lap's first/last parseable telemetry plus its original first/last frame record; these boundary exceptions prevent empty laps and missing endpoints and may exceed the target locally. Preserve all frames inside segment-context regions and every segment/context marker. Do not interpolate, duplicate or upsample.
- F1 contains interleaved packet families: apply independent admission phases to `F1_PACKET_IDS.MOTION`, `CAR_TELEMETRY`, and `MOTION_EX`; preserve all other packet IDs unthrottled, especially session/lap/event/identity state. Use existing `parseF1Header` and constants in `packages/capture-formats/src/f1-2025/f1-wire.ts`. Preserve frame order. Advertise the target as telemetry sample frequency, not a cap on total raw F1 packet count.
- iRacing has a second, source-level delta chain in addition to sparse recording deltas. Decode **every** original source frame via `createIRacingSourceDecoderState` / `decodeIRacingSourceFrame`; immediately encode each selected fully reconstructed source snapshot through a fresh `IRacingSourceFrameEncoder` before sparse encoding. Never copy selected iRacing delta payloads unchanged. Reset source decoder/encoder and sparse encoder at segment boundaries; preserve context fully and reset output encoder after context end so the next telemetry record is independently initialized. Reuse `packages/capture-formats/src/iracing/source-frame.ts` APIs; invalid source-level decoding aborts the group.
- Pass two emits selected frames, rebuilt sparse checkpoints and metadata through canonical recorder/framing primitives. Recompute header count. For each lap, new `rawByteOffset` is its retained original starting record's new decompressed offset; new `rawFrameCount` is the number of **all retained frame records** in its old window, excluding metadata. Because original start/end records are forced, the new span remains contiguous even with overlapping windows. Do not redetect laps, call `replaceLapsForSession`, or change IDs, notes, favorites, tunes, lap times, validity, sectors or experiment/profile/setup relationships.
- Write to a unique sibling `<stem>.downsample-<uuid>.bin` or `.bin.gz`, preserving source compression, via an exclusive temp file; never overwrite source or a conflicting target. Finalize/fsync and strictly replay-validate the target, including all remapped lap windows and reconstructed iRacing values, before publication. If no frames are removed, retain the source and mark the established target cap without replacing it. If the replacement is not smaller on disk, remove it and report `not-smaller` without claiming conversion or savings.
- Add a purpose-built atomic publication query in `server/db/lap-reprocessing-queries.ts`: `commitSessionDownsample(input: { oldRawFile: string; newRawFile: string; sessionIds: number[]; targetHz: RecordingFrequencyHz; lapIndexes: ReadonlyArray<{ lapId: number; expectedRawByteOffset: number; expectedRawFrameCount: number; rawByteOffset: number; rawFrameCount: number }> }): Promise<void>`. Within one transaction recheck all old-path references and expected old lap indexes, update every session path/cap and lap raw index, clear `fuelPerLap`/`tyreWear`, invalidate affected `lapMetrics`, `lapAnalyses`, `compareAnalyses` and `lineSpreadCache` following `replaceLapsForSession`'s existing invalidation pattern, and mark affected dashboard capture facts dirty/not-ready. If sampling removes no frames, instead use a cap-only transactional update with the same reference/index checks; leave paths, cached analysis and lap metadata unchanged.
- After commit call existing `cacheDelete` for affected laps and `clearSessionCaptureCache` for old/new sources, then release affected dashboard capture checkpoints using `releaseDashboardCaptureCheckpoint`. Do not republish old capture-derived facts as if unchanged. Unlink source only after DB commit and after confirming no remaining references. File/DB failure before commit leaves source authoritative and removes uncommitted output; postcommit unlink failure reports the leftover, keeps the valid replacement authoritative, and leaves orphan cleanup to remove the old file. Existing orphan cleanup recognizes sibling `.bin`/`.bin.gz` files, so publication ordering makes crashes safe without a new journal. Temporary suffix files from interrupted writes must be recognized and cleaned only by this operation's narrowly named temp-file cleanup under the maintenance lock.

### 8. Use Effect to own recording maintenance and archival job lifecycles
- Create `server/session-capture/maintenance-runtime.ts`, exported by `server/package.json`, owning one lazily created `ManagedRuntime.make(Layer.empty)` per backend lifecycle. No existing Effect runtime was found. Export `getRecordingMaintenanceRuntime(): ManagedRuntime.ManagedRuntime<never, never>` and `disposeRecordingMaintenanceRuntime(): Promise<void>`. Disposal is idempotent: mark admission stopping, await runtime-owned fibers/finalizers, clear disposed singleton for deliberate restart. No runtime per request/file.
- Use `Ref` for admission/status, `Deferred` to acknowledge admission, and `Effect.gen`/`Effect.fn` for orchestration. Atomic `Ref.modify` admission states `idle | maintenance | downsample | stopping` prevent overlap. Busy manual starts return409; scheduled ticks skip. A scheduled pass invokes its internal downsample Effect in the admitted fiber, never a facade that reacquires admission.
- In `session-downsample.ts` expose `startSessionDownsample(request: SessionDownsampleRequest): Promise<void>` (admission only), `runSessionDownsampleNow(request: SessionDownsampleRequest): Promise<SessionDownsampleStatus>` (same program awaited), and `getSessionDownsampleStatus(): SessionDownsampleStatus`. Promise/status facades are integration boundaries; no `Effect.run*` inside Effect programs. Manual work uses shared runtime `runFork`, never a request-scoped child or detached Promise. Deferred acknowledgement resolves only after worker admission/storage acquisition and release-finalizer registration; rejected admission settles it with typed busy failure.
- Shared `SessionDownsampleStatus` remains `{ status: "idle" | "running" | "success" | "partial" | "error"; request: SessionDownsampleRequest | null; done: number; total: number; convertedFiles: number; freedBytes: number; skipped: SessionDownsampleSkip[]; failed: { sessionIds: number[]; message: string }[]; error: string | null }`. Keep it in a Ref; expose immutable snapshots. `total` counts actionable groups; `done` counts attempts including failure/not-smaller; preflight skips are separate. Zero work/full completion without failures is success; failures with successful conversions are partial; interruption/failures without conversion are error. Keep terminal status until next job. Retry skips established caps.
- Extend `StorageOperation` in `storage-activity.ts` with `"downsample"`; acquire `reserveRecordingStorageOperation("downsample")` through `Effect.acquireUseRelease`. Preserve busy codes; change `MOVE_ACTIVE` message to `Recording storage operation is active`. Finalize admission/status with `Effect.ensuring`, including interruption/defects. Log defects at runtime boundary and set terminal error, never leave a dead job apparently running.
- Preserve `withSessionCaptureMaintenanceLock` as the shared lock with non-Effect cleanup/reprocessing/favorite operations, not an isolated Effect-only semaphore. Plan/rewrite each group under that lock; recheck references/favorites/active capture before publication. Acquire once per group from the Effect loop, never recursively inside an already locked helper.
- Bridge Promise I/O with `Effect.tryPromise` and published `Schema.TaggedError` classes: `RecordingMaintenanceBusyError` (code/message), `RecordingMaintenanceValidationError` (operation/message), `RecordingMaintenanceIOError` (operation/message/cause via `Schema.Defect`). Map to HTTP400/409/500 and per-file summaries; retain Zod at current settings/HTTP boundaries. Do not broadly rewrite DB/file APIs.
- **Interruption safety:** interrupting an Effect does not stop an already-started Promise. Wrap each non-cancellable locked file operation in `Effect.uninterruptible(Effect.tryPromise(...))`, await settlement, then permit interruption between groups. Final validation + DB publication + unlink bookkeeping are one protected unit. Never release a lock/reservation while its I/O runs. Rollback/finalizers finish before shutdown resolves. Existing whole-pass Promise compression/deletion calls are awaited uninterruptibly too; stopping may wait for them. Cancellation cannot undo committed data.
- Refuse active capture/pending layout migration at admission; recheck after lock, between groups and before publication. Capture starting aborts the uncommitted group with original unchanged. No Cancel API. Jobs survive browser navigation, not backend restart; committed paths/caps permit safe later passes. No distributed scheduler/durable-workflow engine or exactly-once crash guarantee.
- In `compressor.ts`, one maintenance Effect performs compression → fresh validated retention settings → automatic downsample → automatic deletion → orphan/staged-import cleanup. Await retention stages in order; no parallelism across them. Automatic downsample uses saved age/Hz. Its failure/interruption skips deletion that pass; ordinary skips do not. Disabled downsample preserves deletion; manual deletion remains independent.
- Keep `runSessionCaptureMaintenanceNow(): Promise<void>` as awaited facade. Replace `_interval`, `setInterval`, `clearInterval`, and fire-and-forget `runMaintenance` with one runtime-owned `Effect.repeat(passEffect, Schedule.spaced("5 minutes"))` fiber: immediate first pass, then five minutes **after completion**, no backlog/overlap. Catch/report recoverable pass failures before repetition so one failure does not kill scheduling. No automatic destructive retries.
- Preserve idempotent `startSessionCompressor(): void`. Change `stopSessionCompressor(): Promise<void>` to stop admission and await runtime disposal, including manual archival fibers. In `apps/backend/src/runtime/shutdown.ts`, await it inside existing try/finally before ingress stops/flush/process exit; preserve remaining shutdown order. `startup-jobs.ts` keeps its start call. Enumerate existing references with `grep` pattern `\\b(startSessionCompressor|stopSessionCompressor|runSessionCaptureMaintenanceNow)\\b` over `apps;server;packages`; query LSP references before signature change and await stop in every caller/test teardown.
- Storage routes remain POST `/api/storage/session-downsample/preview` ->200 read-only preview; POST `/api/storage/session-downsample` ->202 `{ accepted: true }` after worker acknowledgement; GET `/api/storage/session-downsample` ->200 snapshot. Strict invalid request/JSON ->400 `{ error: "Invalid downsample request" }`; recording/storage/job conflict ->409; unexpected admission I/O ->500. Routes call Promise facades only, with no own timers or client-selected file paths.
