# Recent-session race strategy generation contract

Status: agreed boundary derived from the user's request: users choose track, car, laps and weather on Strategies; sessions and evidence stints are automatic and multiple recent sessions contribute. Plans: [UI](recent-session-generation-ui-plan.md), [backend](recent-session-generation-backend-plan.md). Integration owner: main coordinator.

## Authorities and scope

Extend `shared/racing/live/race-plan.ts`, `packages/race-strategy/contracts/generate-race-plan.ts`, existing plan CRUD and feature host RPC. Preserve refueling rules, LMU energy constraints, tire thresholds, ownership, native semantics, source validation and combo pins from [race strategy](../../advisor-plans/race-strategy-contract.md) and [combo strategy](combo-strategy-contract.md). Existing manual and single-source saved plans remain valid. No new tables, migration, dependency or configuration.

## Boundary

- `GET /api/race-plans/generation-evidence?gameId=<GameId>&carId=<string>&trackId=<string>&weather=<any|dry|wet>` uses existing authentication and required validated fields. Response `{baseline: RacePlanBaseline | null}`. Invalid request: 400 `INVALID_RACE_PLAN`; storage failure: existing application 503. Null means no eligible evidence, not a failed read. No session/stint request parameter.
- UI offers Track, Car, Total laps and Weather controls, defaulting track/car to latest owned session for the page's game. Track/car choices come from the existing game catalogues even with no session history; union recorded identities absent from the catalogue to preserve discovered content. Use named options and explicit Select track/Select car placeholders, never Unknown as the only choice. No session or evidence-stint picker. Catalogue loading/errors expose status/retry independently of missing measured history. Weather options: Any recorded conditions, Dry, Wet. Any permits unknown-weather sources with an explicit limitation. Unsupported conditions yield unavailable, not guessed rates. Existing name/capacity/reserve and optional timed-race inputs remain.
- Within requested combo examine the five most recent owned sealed/non-recording sessions, ordered creation timestamp descending then ID descending. Existing capture-free persisted sessions retain recalculation eligibility. Ignore active/unsealed captures, opponents, malformed payloads, identity mismatches, invalid/missing metrics and unknown semantic versions. Bound sources to the 100 most recent eligible stints.
- Newest eligible stint matching requested weather defines PI, fuel unit, setup key, four-wheel compound tuple and semantic versions. Combine only sources matching those fields and weather category exactly. Do not mix compounds, weather categories, fuel units, setups, semantics or Forza PI. Unknown compounds remain unavailable. One eligible session suffices; multiple compatible sessions must contribute when present.
- Weather classification is an explicit projection of trustworthy measured conditions, never inferred from fitted compounds or a fabricated scaling factor. Existing numeric F1 weather 0–2 maps dry, 3–5 wet. New LMU strategy evidence records dry/wet only from available finite native rainIntensity in [0,1]; zero is dry, positive is wet. Known dry/wet transitions split the measured stint so one weather category never labels mixed-weather samples. Recognized stored dry/wet categories are usable. Unknown/missing weather stays unknown; Any is the honest path for histories without weather evidence. Never consume ACC's synthetic WeatherType or hardcoded zero rain. Preserve native channels unchanged. No historical rebuild solely to invent weather.
- `RacePlanBaseline` is a distinct aggregate, not a fabricated `StintSummary`. Reuse summary field types for `gameId`, `carId`, `trackId`, `pi`, `fuelUnit`, `compounds`, `compatibility`, `fuel`, `tires`, optional `virtualEnergy`, `averageLapSeconds`, `paceLaps`; add `weather: dry|wet|unknown` and `sources: StintSummary[]`. Per-metric means are eligible-lap weighted; pace uses paceLaps. Counts are sums. Sources retain real IDs/dates/values. Example fuel rates .02/.04 with counts 2/6 yield .035, count 8, not .03 or newest value alone.
- Add optional `sourceStints: {sessionId:number,stintId:string}[]` to plan stint input: nonempty, unique, max 100, mutually exclusive with legacy non-null sourceSessionId/sourceStintId. Multi-session generated stints use null legacy refs. Add optional nullable `baseline: RacePlanBaseline` to saved stint, retaining legacy evidence unchanged. Add optional plan `weather: any|dry|wet`, with legacy omission interpreted as any. Server validates/resolves every source and computes baseline on save; do not trust client aggregate rates. Saved plans preserve actual aggregate/source snapshots across restart and source deletion. Editing unchanged saved aggregate refs must preserve the saved snapshot rather than silently replacing it with new history.
- Generation uses aggregate rates with existing minimum-stop/resource helper, yielding an unsaved editable draft carrying all source refs. Every affected preview/projection/live-adherence/timed-pace/clone/edit/recalculate consumer uses aggregate metrics when present, legacy evidence otherwise. Recalculation of an aggregate plan retains multi-session semantics and selected weather.
- UI host adds generationEvidence(gameId:GameId, carId:string, trackId:string, weather:RacePlanWeather):Promise<unknown> using typed Hono RPC, plus useTracksForGame/useCarsForGame query hooks exposing neutral {id:string,name:string,variant?:string} rows. Reuse the application catalogue queries/endpoints rather than importing another feature's UI or inventing endpoints. Shared response schema validates evidence payloads. Shared pure aggregation and evidence-access helpers avoid duplicate weighted-mean logic. No raw fetch or fake production fallback.

## State and failure handling

Loading and read errors disable generation; errors expose retry and are not empty history. Changing track/car/weather clears resource-capacity/error state and invalidates incompatible draft source state. sessionId navigation hints never restrict history or reintroduce session selection. Save validates all source refs atomically; missing/mismatched sources reject with current source errors while preserving draft. Unsupported weather is unavailable, never a fallback to unrelated conditions. Zero rates remain valid measured values. Existing timed mode requires measured pace. User-selected weather is persisted separately from measured source weather category.
