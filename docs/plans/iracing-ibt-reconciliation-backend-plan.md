# Automatic iRacing IBT reconciliation: backend implementation plan

Status: proposed; not implemented or verified.

Shared boundary, policy, acceptance and E2E: [Reconciliation contract](iracing-ibt-reconciliation-contract.md). Decision: [ADR 0015](../adr/0015-automatic-iracing-ibt-reconciliation.md). Parallel implementation: [UI plan](iracing-ibt-reconciliation-ui-plan.md).

## Scope and ownership

Implement automatic local discovery and safe attachment of IBT evidence to existing live-recorded sessions. Preserve live-only data and original bytes; enrich semantic replay without changing primary recording format or creating imported duplicate laps. Backend owner also owns shared schemas, contract updates and final cross-layer E2E execution. Do not invoke destructive session reprocessing or race-result reconciliation.

Owned existing integration points:
- `apps/backend/src/runtime/iracing-capture.ts`: collection events, enabled-state restoration and historical inventory.
- `packages/game-iracing/src/disk-logging.ts`: existing Known Folder/closed-file/atomic archive primitives; preserve native logging ownership semantics.
- `packages/game-iracing/src/ibt-reader.ts`, `ibt-source.ts`: stream complete variable table, native segment identities and row offsets; do not reuse standalone import's complete-lap eligibility for reconciliation.
- `packages/capture-formats/src/iracing/{source-frame,session-info}.ts`: existing native identity and metadata definitions.
- New dedicated Bun reconciliation worker entry point, parent supervisor, typed bridge and worker-owned durable Effect runtime beside `apps/backend/src/runtime/startup-worker.ts`; appended domain migrations/queries and a separate owned workflow journal. Reuse `server/db/worker-sql.ts` and parent write/maintenance authorities; do not create another hand-built scheduler or application DB writer.
- `server/telemetry/replay.ts`, `server/db/telemetry-replay-storage.ts`, source loader and attachment-aware export/retention paths in `apps/backend/src/laps/archive.ts` and `server/session-capture/`.
- `apps/backend/src/routes/games/iracing.ts`: shared summary/session status APIs.
- `packages/scene-3d/src/wireframe/ScenePlacement.ts`: reference-only fit validation and truthful geometry status; shared/server policy must not drift from scene behavior.
- Existing native capture tests and seeded Playwright session/analysis/compare tests; backend owner adds paired fixtures and integration scenarios.

Do not change Connection UI or translations. UI owner can implement immediately against contract-conforming fixtures once boundary is accepted. Backend publication and real UI integration are the genuine shared completion dependency, not prerequisites for UI implementation.

## Tasks and acceptance mapping

0. **Bun worker and durable Effect runtime prerequisite — RC-05/07/09/10.** Run pinned Effect 4.0.4 Workflow/Activity and SQL-backed SingleRunner/ClusterWorkflowEngine inside one dedicated Bun-hosted `node:worker_threads` Worker. Parent supervises lifecycle and native SQL hosts; worker owns workflow/activity execution and the Effect journal SqlClient facade through the typed parent bridge. Follow existing startup-worker dev/compiled entry resolution, not a worker per job. Validate adapter compatibility on Bun/Windows, journal migrations, restart and shutdown before integration; no core Effect upgrade, in-memory engine or main-thread fallback. Define worker-generation/request IDs, bounded controls and durable intent acknowledgements against the shared contract. UI implementation remains independent.


1. **Durable attachment model and shared API types — RC-02/03/05/07/08/09.** Append domain migration for file inventory generations, immutable owned source identities, segment/range attachments, revisions, counters, processing version, durable submission/refresh outboxes and execution-keyed publication receipts. Workflow engine journal owns execution history; domain state/reason/stage is its fenced read projection, not a second scheduling authority. Multiple attachments may serve one session; one IBT may serve multiple sessions. Add unique constraints preventing duplicate source/range publication and duplicate revision increments after activity replay. Preserve primary session source/rawFile, IDs and metadata. Shared API types include nullable workflow stage/wake metadata and supplemental provenance; preserve route authentication/errors.
2. **Automatic discovery and catch-up — RC-01/05/07/09.** Extend existing capture manager rather than create another independent native collector. On enabled startup/file changes inventory owned archives and resolved telemetry directory, including pre-existing files. Header-index historical candidates against live-session identities before copying unrelated history. Persist changed-file state in bounded batches, with a durable workflow submission outbox before event acknowledgement. Deliver archive-publication/live-finalization intents idempotently; recover missed notifications by inventory scan. Reuse settled-metadata/exclusive-close checks and immutable publication. No whole-disk search, symlink traversal, native mutation, unrelated bulk import or extra confirmation. Preserve opt-in, disconnect and logging ownership.
3. **Segment matching and range index — RC-02/03/04.** Implement exact native identity and overlap proof from contract, including placeholder-ID handling and driver identity metadata absent from the normalized snapshot. Partition restarts/session changes/car entries before indexing. Stream each candidate once per attempt; keep bounded matching state and persist selected-lap row/range indexes. Deduplicate same bytes; combine disjoint proven ranges; reject ambiguous/conflicting overlap rather than overwrite a prior result. No filename/lap-number/time-nearest matching. Retain all IBT bytes even where rows do not map to live frame grid.
4. **Worker activities, fenced publication and recovery — RC-03/05/08/09/10.** Execute archive/index/match/publish/refresh and fit preparation on the dedicated Bun worker's durable Effect runtime. Main thread performs only supervision, bounded message routing and admitted native SQL work. Preserve activity results, durable waits/timers and typed retries. Use parent-owned application leases plus isolated journal SQL host; never rely on a worker-local application gate or share native handles. Publication atomically records execution receipt, attachments, revision and refresh intent. Fence worker generation and source/baseline. On exit/channel loss drain parent SQL and roll back/close native transactions before lease release or replacement; wait for actual worker exit. Stop gracefully after I/O settlement; crashes resume same journal without full-pipeline replay or inline fallback. Keep referenced sources/native originals safe.
5. **Semantic replay and provenance — RC-03/04/06.** Resolve base live data first; supplement only segment-dictionary-absent channels on exact unique native keys. Do not attach IBT packets by array index or overwrite invalid live samples. Extend diagnostics to attribute supplemental observations to IBT source/row without replacing primary provenance. Use selected-lap index reads; invalidate/cache-key all affected semantic replay, compare and pose artifacts by reconciliationRevision. Preserve indexed/live-member bootstrap and raw frame-window invariants. Missing/corrupt attachment degrades supplemental availability with explicit status, not loss of live replay or synthetic zeros.
   Implement against the shared contract's [non-GPS inventory](iracing-ibt-reconciliation-contract.md#non-gps-enrichment-inventory), not a GPS-only allowlist: candidate additions include wheel speeds, tyre pressures/surface temperatures, ride heights and ABS reduction; suspension, brake-line pressure, steering torque/subsamples and motion supplement only when absent live. Preserve units, scalar/array shape and catalog freshness/support; original-channel retention does not authorize invented mappings, timestamps or analyses. Execute RE-04b for RC-03/04/07/08, including cold replay and transfer.
6. **Measured scene and fit guard — RC-04/06.** Feed reconciled Lat/Lon/Alt/YawNorth through existing semantic pose resolver; keep native XYZ capabilities disabled for iRacing. Apply contract fit coverage/residual/orientation policy to official reference only. Share geometry diagnostics with session status. Partial/gapped laps and poor/reversed fits cannot claim accepted track alignment. Reject overlay while retaining measured path. Never persist global track calibration or invent optimal line/tire-trail support.
7. **Status, transfer and documentation — RC-05/07/08.** Implement contract capture-summary extension and session status endpoint; preserve access checks, feature gating and existing PUT body. Persist counters/outcomes rather than use runtime savedFiles as reconciliation success. Extend archive manifest/readers to carry both original sources and attachment indexes/provenance, with backwards reading of single-source exports. Update adapter, game collection, track replay docs and Unreleased changelog once the coherent implementation is verified.

## Edge handling and verification ownership

The shared contract is authoritative for every edge and expected result; do not redefine thresholds or precedence here.

| Backend boundary | Strategy and required shared E2E |
| --- | --- |
| Startup history, redirection, unsupported/disabled host, unrelated paths | Reuse opt-in/Windows resolver; bounded matched-only catch-up; explicit status. RE-01/02; RC-01/05/07/08. |
| Zero IDs, wrong driver/layout, restart ticks, multi-file/multi-session and overlap conflict | Partition native identity; exact-key overlap proof; limit ambiguous inputs; deduplicate equivalents and reject new conflicts. RE-03; RC-02/03/04/05. |
| Different cadence, missing heading/GPS, invalid live channel, duplicate identity, partial IBT | Add only missing channels at exact keys, never fill gaps or overwrite live states; partial source can enrich without geometry acceptance. RE-04; RC-03/04/06. |
| Open writer, changing/corrupt/missing source, process crash | Closed-file/generation rechecks, durable work state, immutable copy, fenced atomic publication and visible limitation/recovery. RE-05/08; RC-01/05/08. |
| Active source, disconnect, stale revision, delete/retention/relocation | Defer final publication, preserve accepted work, fence current existence/revision, protect owned references. RE-06; RC-03/05/08. |
| Hot/cold replay cache, comparison, fit rejection and export/import | Revision-aware readers and provenance; reference-only policy; preserve both sources during transfer. RE-07/08; RC-03/04/06/07/08. |
| Durable execution, retries, stage projection and journal/domain transaction gap | SQL-backed Effect engine, evidence-keyed identities, named activity results, durable waits/wakes, submission/refresh outboxes and idempotent domain receipts; no second queue or blanket exactly-once claim. RE-09; RC-03/05/06/07/09. |
| Bun worker boundaries, compiled entry, crash/channel loss and backpressure | Dedicated worker engine/activities, bounded versioned control bridge, parent-owned native SQL and generation fencing; await actual exit plus SQL drain before replacement, no inline fallback. RE-10; RC-03/05/06/07/09/10. |

Execute real production-entry scenarios RE-01–10 after both implementations integrate. Extend existing native capture harness/seeded Playwright suite with isolated domain DB/data dirs, persisted journal and actual Bun reconciliation worker. RE-09 verifies process-restart durability; RE-10 additionally proves non-main thread identity, live/HTTP progress during worker activity, crash/channel-loss cleanup, single replacement, bounded controls and dev/compiled worker resolution. Test barriers may control sequencing but cannot replace worker/SQL/engine integration. Run applicable regression/project gates once edits settle and record outcomes. Real compiled Windows simulator/locking/redirected-folder evidence remains mandatory.

Completion evidence must map RC-01–10 and all edges to passing E2E, including exact source/provenance conservation, preserved IDs/live-only data, durable Effect recovery and actual Bun worker isolation/parent SQL cleanup. In-memory engines, Promise-only offloading and planned smoke are not proof. Missing environment/dependencies remain explicit blockers. Document this durable worker runtime without claiming unrelated maintenance jobs became durable. No implementation, tests, commits or checkpoints are authorized by this planning-only request.
