## Baseline and boundaries

Implemented source is the starting point, not a request to rebuild Online. Published SDK `@speedhq/live-client@0.2.1`, consumer pinning, genuine F1/LMU upload/archive proofs, selected Community replay paths, same-original second-instance deduplication, lost-acceptance crash recovery, and selected HTTP abuse fences already have evidence. Older reports saying the SDK is unpublished or these upload recovery scenarios are untested are superseded. Two isolated instances on one host are not physical-device or Windows certification; lap deduplication is not lifetime-statistics merge acceptance.

Preserve immutable originals, owners, GUIDs, historical binding snapshots, raw native bytes and clocks. Never convert Unknown to Self, invent original coverage, remint identity to bypass conflict, modify released migrations, or manipulate Effect-owned queue tables for recovery. Keep Forza recording rejection and F1 World car41 competition scope. No account switching, profile picker, new statistics opt-in, authenticity guarantee, UI redesign or new endpoint is proposed. Reuse the shared contract and current code; any necessary boundary change must update the shared contract and both affected implementation plans before implementation.

All attack traffic remains loopback-only with isolated storage, fake local auth and bounded workloads. Preserve the existing seeded services, shared proxy/terminals and original recordings. Do not inspect dependency source or add dynamic imports. Security/private code remains inline unless an authorized trusted execution route is available; do not share it with free providers. ACC fixture hunting remains parked; iRacing recording investigation remains excluded. Their release requirements are not waived.

## Failure handling and evidence rules

- Revocation, worker/account generation changes and stale results fail closed; restore does not make an old authorization current. Keep original bytes, owners, timestamps and accepted receipts.
- Ambiguous network success reconciles against owner receipt using the durable identity. Definite no-send can retry under current authorization; a conflict is held, not reminted or silently rebased.
- Expired/replaced/cross-account reservation secrets cannot authorize transfer. Concurrent losers may receive the existing contract's locked/already-accepted/expired outcome; assert immutable canonical state and no duplicate credit rather than one arbitrary race status.
- Missing source, native attribution, positive fixture, Windows/staging access or legal approval remains a named blocker. Do not reduce required games or replace actual E2E with static checks or mocks.
- Retain full logs, request counters, build IDs, expected/observed summaries and selected screenshots as durable evidence under the existing `.omp/evidence/` conventions. Redact credentials/private native descriptors. Each R/V record states passed, failed, blocked or not run, environment, exact command and links.
- Execute relevant V scenarios after implementation; there is no new runtime acceptance in this plan. Existing evidence is reusable only for unchanged relevant inputs and matching scope. Source/config/dependency/fixture/environment changes invalidate affected checks, not unrelated successful gates.
- After changes settle: desktop `bun run typecheck`; affected capture/native/Online/dashboard/import regressions; cloud workspace typecheck, upload/API and relevant processor/retention checks; actual app/browser smoke; locale/accessibility checks when touched; compiled Windows/release/restore checks for P3. Update user docs/changelog once per coherent proven change and remove owned temporary scaffolding, preserving requested seeded services.

## Explicit blockers and completion

ACC positive attribution fixtures, Evo acceptance of available recordings, excluded iRacing investigation, twelve-original retention coverage, physical/Windows environment, hosted/staging authorization and operator legal approval remain unproven prerequisites. Inventory them in P0 and proceed with independent reachable slices; do not repeatedly hunt parked fixtures or request production sign-in as a substitute.

Release completion requires every R01–R22 item and its full shared E01–E19 mapping to have passing application/system-entry evidence, plus applicable current gates and authorized release review. Partial, planned, blocked or skipped scenarios never count as complete. Native unsigned telemetry and account-reported totals remain non-attested; this plan does not promise complete anti-cheat or unlimited denial-of-service resistance.
