28## Supported datatypes
29`configparser` does not guess the datatype of values in configuration files and stores everything as strings. However, some datatypes are so common
30that it's a safe bet that some values need to be parsed in other types. For this, the `Ini` struct provides easy functions like `getint()`, `getuint()`,
31`getfloat()` and `getbool()`. The only bit of extra magic involved is that the `getbool()` function will treat boolean values case-insensitively (so
32`true` is the same as `True` just like `TRUE`). The crate also provides a stronger `getboolcoerce()` function that parses more values (such as `T`, `yes` and `0`, all case-insensitively), the function's documentation will give you the exact details.
33```rust
34use configparser::ini::Ini;
35
36let mut config = Ini::new();
37config.read(String::from(
38  "[somesection]
39  someintvalue = 5"));
40let my_value = config.getint("somesection", "someintvalue").unwrap().unwrap();
41assert_eq!(my_value, 5); // value accessible!
42
43//You can ofcourse just choose to parse the values yourself:
44let my_string = String::from("1984");
45let my_int = my_string.parse::<i32>().unwrap();
46```

49## Supported `ini` file structure
50A configuration file can consist of sections, each led by a `[section-name]` header, followed by key-value entries separated by a `=`. By default, section names and key names are case-insensitive. All leading and trailing whitespace is removed from stored keys, values and section names.
51Key values can be omitted, in which case the key-value delimiter (`=`) may also be left out (but this is different from putting a delimiter, we'll
52explain it later). You can use comment symbols (`;` and `#` to denote comments). This can be configured with the `set_comment_symbols()` method in the
53API. Keep in mind that key-value pairs or section headers cannot span multiple lines.
54Owing to how ini files usually are, this means that `[`, `]`, `=`, ';' and `#` are special symbols (this crate will allow you to use `]` sparingly).
55
56Let's take for example:
57```INI
58[section headers are case-insensitive]
59[   section headers are case-insensitive    ]
60are the section headers above same? = yes
61sectionheaders_and_keysarestored_in_lowercase? = yes
62keys_are_also_case_insensitive = Values are case sensitive
63;anything after a comment symbol is ignored
64#this is also a comment
65spaces in keys=allowed ;and everything before this is still valid!
66spaces in values=allowed as well
67spaces around the delimiter = also OK
68
69
70[All values are strings]
71values like this= 0000
72or this= 0.999
73are they treated as numbers? = no
74integers, floats and booleans are held as= strings
75
76[value-less?]
77a_valueless_key_has_None
78this key has an empty string value has Some("") =
79
80    [indented sections]
81        can_values_be_as_well = True
82        purpose = formatting for readability
83        is_this_same     =        yes
84            is_this_same=yes
85```
86An important thing to note is that values with the same keys will get updated, this means that the last inserted key (whether that's a section header
87or property key) is the one that remains in the `HashMap`.
88The only bit of magic the API does is the section-less properties are put in a section called "default". You can configure this variable via the API.
89Keep in mind that a section named "default" is also treated as sectionless so the output files remains consistent with no section header.

91## Usage
92Let's take another simple `ini` file and talk about working with it:
93```INI
94[topsecret]
95KFC = the secret herb is orega-
96
97[values]
98Uint = 31415
99```
100If you read the above sections carefully, you'll know that 1) all the keys are stored in lowercase, 2) `get()` can make access in a case-insensitive
101manner and 3) we can use `getint()` to parse the `Int` value into an `i64`. Let's see that in action.
102
103```rust
104use configparser::ini::Ini;
105use std::error::Error;
106
107fn main() -> Result<(), Box<dyn Error>> {
108  let mut config = Ini::new();
109
110  // You can easily load a file to get a clone of the map:
111  let map = config.load("tests/test.ini")?;
112  println!("{:?}", map);
113  // You can also safely not store the reference and access it later with get_map_ref() or get a clone with get_map()
114
115  // If you want to access the value, then you can simply do:
116  let val = config.get("TOPSECRET", "KFC").unwrap();
117  // Notice how get() can access indexes case-insensitively.
118
119  assert_eq!(val, "the secret herb is orega-"); // value accessible!
120
121  // What if you want remove KFC's secret recipe? Just use set():
122  config.set("topsecret", "kfc", None);
123
124  assert_eq!(config.get("TOPSECRET", "KFC"), None); // as expected!
125
126  // What if you want to get an unsigned integer?
127  let my_number = config.getuint("values", "Uint")?.unwrap();
128  assert_eq!(my_number, 31415); // and we got it!
129  // The Ini struct provides more getters for primitive datatypes.
130
131  // You can also access it like a normal hashmap:
132  let innermap = map["topsecret"].clone();
133  // Remember that all indexes are stored in lowercase!
134
135  // You can easily write the currently stored configuration to a file like:
136  config.write("output.ini")?;
137
138  // If you want to simply mutate the stored hashmap, you can use get_mut_map()
139  let map = config.get_mut_map();
140  // You can then use normal HashMap functions on this map at your convenience.
141  // Remember that functions which rely on standard formatting might stop working
142  // if it's mutated differently.
143
144  Ok(())
145}
146```
