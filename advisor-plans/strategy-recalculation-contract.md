Existing storage/auth contracts remain [race plan schemas](../shared/racing/live/race-plan.ts), [stint schemas](../shared/racing/live/strategy-schemas.ts), and feature route middleware. ## Decisions and ownership

User explicitly wants new suggested strategies reflecting improved pace, wear and energy consumption, not a forecast-only refresh. Clone and clone/recalculate are separate reviewable drafts; neither changes the source plan or active selection. Explicit save creates a new ID. Recalculation uses the latest eligible completed owned session for each compatible compound profile, not an all-history average that conceals improvement.

Coordinator owns shared schemas, UI host/RPC composition, integration, verification, documentation and approved checkpoint. Metric implementation owns lap aggregation/accumulation/context and metric tests. Regeneration implementation owns server selection/proposal, generation math and server tests. UI owns design primitives, generator/editor/list, localization and browser scenarios. Shared schema changes precede independent implementation; changes to this boundary update both plans.

## Shared shapes

`RacePlanInput.generation?: RacePlanGeneration | null`, with schema default `null` for stored/manual legacy plans. `RacePlanGeneration = { fuelCapacity: number; fuelReserve: number; energyReserveFraction: number }`. Fuel fields use the plan's existing `fuelUnit`; they are finite, capacity > 0, 0 <= reserve < capacity, fraction capacity <= 1. Energy reserve is a remaining-budget fraction in [0,1). Generated plans persist these constraints; editor saves/loads and cloning preserve them. No database migration: plan payload already stores validated JSON.

`MetricRate.unit` adds `energyFraction/lap`. `StintSummary.virtualEnergy?: MetricRate` and `CompatibilityContext.virtualEnergySemanticVersion?: string | null` are optional so immutable historical plan snapshots remain readable. Newly computed LMU summaries include measured native `lmu.virtualEnergy` consumption, independent of fuel liters and battery state of charge. Unsupported/missing samples produce unavailable energy, never zero or fuel aliases. Lap contribution adds optional `virtualEnergyUsed` and `virtualEnergyExcludedReason`. Accumulator includes independent energy numerator/count. Bump strategy algorithm to `stint-metrics-v3`; existing versioned startup replay rebuilds stale summaries without editing stored laps. Virtual-energy increases are resource-refill boundaries, not negative consumption.

## Operation

`POST /api/race-plans/:id/recalculate` uses existing authenticated/CSRF-protected route composition. Body: `{ generation: RacePlanGeneration }` (required, strict); existing plan supplies identity, race length, fuel unit, notes, compounds and compatibility snapshot. Success 200: `{ draft: RacePlanInput, sources: StintSummary[] }`. Draft has no saved ID. `sources` contains the actual selected summaries, deduplicated in compound-phase order; UI displays session/date, eligible laps, pace and resource rates. No writes or active-plan changes occur.

Errors: 400 `INVALID_RACE_PLAN` for malformed constraints; 404 `RACE_PLAN_NOT_FOUND`; 422 `RACE_PLAN_EVIDENCE_UNAVAILABLE` when no compatible measured evidence/pace/resource budget exists or a proposal cannot fit one lap, exceeds 100 stints or invalidates a retained compound-change anchor. Storage failures remain real server errors, no fake proposals. UI retains inputs and original plan on failure.

Latest-source eligibility: same game/car/track, local-player driver, owned session, completed/interrupted stint with endedAt, matching fuel unit, four compounds, setup key and known measurement semantic versions from the corresponding original evidence. Forza PI must be known/equal. Active recording/finalizing/recovering sessions are excluded. Require usable fuel/four-wheel wear and pace; LMU additionally requires usable measured virtual energy. Sort session createdAt descending, session ID descending, stint endedAt descending, ordinal descending, ID ascending; choose first eligible source. Unknown original setup is allowed only against unknown setup and remains explicitly uncertain. Missing original identity/semantics is not permission to borrow unrelated evidence.

Recording admission also checks the live pipeline's per-session recording/retirement ownership under the existing capture-maintenance lock. A missing `live_captures` row alone does not prove that a UDP recording is legacy or sealed. Closed legacy recordings remain usable while another session records; direct captures still require a sealed journal state.

Suggestion algorithm: reuse one pure feature-owned server/browser-safe generator. Fuel limit = floor((capacity - reserve)/fuel rate); tire limit = earliest configured per-compound cliff from fresh tires; LMU energy limit = floor((1 - energy reserve)/energy rate). Zero measured consumption imposes no limit; missing consumption is not zero. Use roundoff-safe exact-fit integer boundaries. Greedily choose maximum safe stint lengths and trim last stint to finish. Refuel projections include reserve. Repeated same-compound original stints form one phase and may merge; retain actual compound-change laps as anchors. Different compounds are never silently removed. For timed races preserve duration, use latest selected measured pace (phase-lap-weighted for mixed profiles) and recompute ceil(duration/pace); reject impossible compound anchors rather than truncate them. Lap-based races retain total laps. Each stop assumes fresh tires, refueling and a full LMU virtual-energy budget; show these assumptions, not an optimal-race-time claim.
