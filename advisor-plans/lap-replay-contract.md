# Lap replay package contract

Status: implementation contract, derived from the existing feature-package architecture and current replay routes. No HTTP, authentication, telemetry, or AI behavior is being redesigned.

Plans: [UI](lap-replay-ui-plan.md), [Server](lap-replay-backend-plan.md). Architecture: [feature packages](../docs/architecture/feature-packages.md).

## Ownership and integration

One workspace, `@raceiq/lap-replay`, owns `ui/`, `server/`, `contracts/`, `test/unit/`, and `test/e2e/`. Public imports are `@raceiq/lap-replay/ui`, `/server`, and `/contracts`; no mixed root or wildcard export. Existing shared analysis, comparison, telemetry, and scene DTOs remain authoritative in their current packages. Move the client-owned semantic replay DTOs into feature contracts without duplicating them.

The package owns the Spectate component tree, replay controller/preparation, line-spread presentation helper, shared Insights rendering and panel workspace. Application routes continue composing session/lap selection, single-lap AI and comparison AI separately. Shared platform controls, translations, authenticated RPC, settings/game context and telemetry/scene primitives are injected through typed host bindings, following the catalogue provider pattern. No package source imports client or backend application composition roots. Do not conceal feature implementation behind untyped host callbacks.

The single replay uses one recorded lap and lap-scoped AI. Compare uses the existing two distinct laps and comparison-scoped AI. Both consume the same workspace and Insights UI; Compare adds the shared A/B selector. No duplicate lap, fake comparison, copied UI, or compatibility re-export remains.

## Existing operations preserved

- `GET /api/laps/:id/semantic-telemetry`: use the existing shared [`IdParamSchema`](../shared/platform/http/route-schemas.ts), with required `X-Game-Id`; return the existing `SemanticLapTelemetry` response. Required fields: numeric `lapId`, `requestedSemanticIds: string[]`, and ordered `envelopes: SemanticReplayFrame[]`. Preserve optional/nullable sector times, sector starts, parse error, findings and detector coverage. Each envelope retains numeric sequence, observed/received `{domain: string, milliseconds: number}`, simulator string, semantic value entries (`semanticId`, unknown `value`, optional nullable `unit`, optional state/freshness), and optional existing LMU wire context. Findings use authoritative `LapInsight`; frame indices refer to the original replay frame array, not aligned comparison indices or sequence numbers.
- `GET /api/laps/:id/insights`: same ID/header rules; `{ insights: LapInsight[] }`.
- `POST /api/laps/:id/insights/rerun`: preserve the existing request, authorization, computation, response and error semantics; no new authentication rule.
- The extracted handlers in [`packages/lap-replay/server/index.ts`](../packages/lap-replay/server/index.ts) preserve exact serialization and errors: invalid/missing game header 400, missing/wrong-game lap 404, replay failure 422, and parse failure represented by the existing successful empty/unavailable response. In particular, an absent committed live member is normally returned as a 200 parse-error/unavailable result by the authoritative lap loader; the existing later 409 guard remains for a publication disappearing between reads. Numeric zero is accepted by the shared ID parser and resolves as a missing lap, not a validation error. Preserve shared middleware and Hono-inferred RPC typing. There is no pagination or new persistence state.

Representative semantic result: `{ "lapId": 31, "requestedSemanticIds": ["motion.speed"], "sectorTimes": null, "sectorStarts": null, "insights": [], "detectorCoverage": [], "parseError": null, "envelopes": [] }`. Actual recorded envelopes and analysis values remain unmodified.
