# Race strategy feature extraction contract

Status: agreed implementation boundary, derived from approved requirements and [feature package convention](../docs/architecture/feature-packages.md). Plans: [UI](race-strategy-ui-plan.md), [server](race-strategy-backend-plan.md). Integration owner: main coordinator.

## Scope and ownership

Create one `@raceiq/race-strategy` workspace at `packages/race-strategy/`, with top-level `ui/`, `server/`, `contracts/`, `test/{unit,integration,e2e}`, one manifest/Turbo configuration and explicit `./ui`, `./server`, `./contracts` exports. No mixed root, wildcard exports, compatibility shims or intermediate `src/`.

Feature owns session stint analysis/comparison; race-plan editor, saved/active plans and live planned strategy; pit estimate/history presentation; live stint/pit tracking, metric accumulation, strategy queries/baselines/plan persistence; recording-backed automatic backfill; exclusively owned tests. Sector timing and shared mathematical primitives serving non-strategy consumers remain platform/foundation responsibilities. Existing shared telemetry DTOs and schemas in `shared/racing/live/{strategy,strategy-schemas,race-plan,tire-thresholds}.ts` remain authoritative; feature contracts define typed host bindings, not copied schemas.

Application retains thin file routes, global session-review tab composition, boot/shutdown, shared DB/schema/migrations/write coordination, shared WebSocket transport, shared controls/settings/game/session hooks, and recording decoding/lap detection. No feature implementation may import client or backend app composition roots. Backend-core must not depend on a feature that imports backend-core. Typed platform ports are registered with real implementations by app composition before pipeline construction; unregistered access throws rather than installing a no-op/fake fallback. Reprocessing invokes the registered strategy reconstruction port while source replay stays platform-owned. Strategy-only replay may detect temporary source windows for association but never writes detector results into, updates, or replaces stored lap rows.

UI receives typed host bindings through provider from `client/src/features/race-strategy-host.tsx`: existing translated messages, shared controls, typed authenticated RPC operations, settings/session/live-telemetry access. Feature owns its query hooks and formatting/projections. Preserve inferred Hono RPC typing; no raw-fetch replacement or unsafe casts. Host errors retain existing response behavior. UI/server may develop independently against these bindings.

The application-owned shared live-dashboard Storybook frame installs the same real UI host provider. It renders the supplied story through a route function so both function and class components satisfy the router boundary; no production fallback or duplicate feature implementation is introduced.

Boundary authorities are [`contracts/ui-host.ts`](../packages/race-strategy/contracts/ui-host.ts), [`contracts/messages.ts`](../packages/race-strategy/contracts/messages.ts), and the neutral [`RaceStrategyRuntime` port](../server/telemetry/race-strategy-ports.ts). The UI host keeps authenticated, inferred Hono requests in app composition; feature hooks validate response bodies with the authoritative shared schemas. `registerRaceStrategyFeature()` supplies real tracker, reconstruction, eligibility, clear and publication operations in both main and worker initialization.

Idle pipeline observations, flushes, WebSocket lap reads and periodic maintenance must not construct a default tracker before application composition. Actual tracking still requires the registered real runtime. Bare test configurations and recording/game suites use the application-owned [`setup-strategy.ts`](../apps/backend/test/support/setup-strategy.ts) preload; ordinary pure-unit runs retain no preloads. This preserves recording helpers without introducing a backend-core-to-feature dependency.

The genuinely shared live-telemetry view and focused tests belong to `@raceiq/frontend-pure`, exported as `@raceiq/frontend-pure/live-telemetry-view`; migrate every consumer rather than introducing a feature-to-client import or copying DTOs. Its package-level dependency invalidation selects race strategy and cars, its actual consuming features, but not tracks solely because the helper is shared.

Coordinator owns package manifest/exports, Turbo/TypeScript setup, root dependency/lockfile updates, root provider composition, boundary/test discovery/impact configuration, plans/checkpoint/evidence and final integration verification. UI implementer owns feature `ui/`, UI host contracts/adapter, migrated UI consumers and browser specs. Server implementer owns feature `server/`, server host/port contracts, backend-core neutral ports, server app composition and exclusively owned Bun tests. Changes to shared boundary update this contract and both plans before dependent work proceeds.

## Existing protocol and state contracts

No protocol redesign. Authorities: [`packages/race-strategy/server/session-strategy-routes.ts`](../packages/race-strategy/server/session-strategy-routes.ts), [`race-plan-routes.ts`](../packages/race-strategy/server/race-plan-routes.ts), and the shared schemas above. `apps/backend/src/routes/session-routes.ts` retains shared middleware and thin feature-route composition.

| Operation | Request | Response / errors |
| --- | --- | --- |
| GET /api/sessions/:id/stints | Positive integer session ID; required valid `X-Game-Id`; optional nonempty `driverKey`. | `{stints: StintSummary[]}` in existing order, nullable metrics and evidence preserved. Invalid request 400; missing/cross-game session 404; storage failure 503, existing codes. |
| Existing pit-estimates/baseline operations | Preserve validated session/game/driver filters and opaque history cursor/limit bounds. | Existing `PitEstimatePageSchema`/`BaselineResponseSchema`; retain ordering, clear generations, pagination, empty states and errors. |
| Existing race-plan CRUD and active-plan operations | Existing validated IDs, `RacePlanInputSchema`, game scoping and nullable active selection. | Existing `RacePlanSchema`, list/active wrappers, not-found/source validation and persistence errors. No fake fallback. |
| Strategy history/clear notifications | Existing game/driver/revision and clear-scope fields. | Publish only committed state; invalidate existing queries; preserve reconnect semantics. |
| Recording-backed backfill | Backend startup scans bounded session pages; each candidate uses its own sealed recording. | Missing aggregate generations and summaries with an outdated algorithm version are rebuilt atomically. Preserve stored lap IDs/times/validity/notes/favorites. Current summaries and completed empty generation markers skip work. Active/missing/corrupt/identity-mismatched recordings preserve prior data and do not prevent independent candidates. Shutdown waits for admitted work, stops between sessions. |

Examples remain `GET /api/sessions/10/stints` with `X-Game-Id: lmu`, and existing plan requests conforming to shared schemas. Global auth/CSRF/origin middleware is unchanged. Public UI routes remain `/$gameid/strategy` and session analyse `view=stints`; Overview and Analyse remain, sector tabs removed only for session review. One stint is analyzable without selection; two selected stints enable optional comparison. No recorded data is fabricated.

The strategy route is a saved-plan list with a separate generator/editor. Generation uses existing stint reads and plan CRUD without new endpoints. It requires owned, sealed local-player evidence with measured fuel and all four tire rates and compounds, a race length (laps or duration using measured pace), explicit tank capacity and a reserve. It proposes constant-rate, minimum-stop stints limited by usable fuel and the earliest configured tire cliff, assuming fresh tires and refueling at each stop. The last stint ends exactly at the race length. Missing evidence, invalid inputs, an inability to complete one lap, or more than 100 required stints produces an actionable error and no plan. Generation remains a draft until explicitly saved.

## Acceptance criteria

- RS-01: Full feature implementation and exclusively owned tests reside in one workspace; callers use public entries, obsolete paths removed, graph acyclic.
- RS-02: Standalone planning, plan CRUD/active/live identity applicability, timed/lap forecasting, thresholds and history retain behavior.
- RS-03: Session review has Overview/Stint averages/Analyse, no sector tabs; current-session table/charts work with one stint; comparison appears only for two selections; empty/error states honest.
- RS-04: Startup automatically backfills missing and outdated aggregates from matching recordings, preserving lap/session metadata; repeat startup is idempotent; unsafe/unavailable candidates cannot corrupt or block independent repairs.
- RS-05: UI/contracts remain transitively browser-safe; typed public boundaries, auth/RPC/notifications/lifecycle preserved; forbidden import probe fails and production browser build excludes native/DB modules.
- RS-06: Existing unit/integration/E2E identities retain exactly one owner; feature E2Es exercise complete compiled real app with isolated data/ports, not development-only or mock app.
- RS-07: UI/server/spec changes select feature E2Es; unrelated-feature edits do not select solely due to full-app build; shared/unknown/missing-history changes remain conservative; no E2E cache change.
- RS-08: Relevant static, build, real-runtime and acceptance E2E gates executed and outcomes recorded; failures/unavailable requirements explicitly reported, never counted as passes.
- G1: The Stint averages generation action opens the strategy route with the current session selected.
- G2: Generated proposals respect the shared generation rules above and retain evidence through real save/edit/reload operations.
- L1: The Strategies page lists every saved plan for the selected game and supports opening, editing, activating, unloading and deleting plans through existing APIs.
- B1: LMU scoring-distance corrections do not invalidate otherwise continuous lap measurements. Timestamp gaps, mixed identities and mixed lap intervals remain excluded.
