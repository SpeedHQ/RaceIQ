# Sessions page feature package contract

Status: implementation contract. Authority: [feature packages](../docs/architecture/feature-packages.md). Plans: [UI](sessions-page-ui-plan.md), [backend](sessions-page-backend-plan.md).

## Ownership

`@raceiq/sessions-page` owns the Sessions listing page, its tables, toolbar, import orchestration, selection/filter/sort/pagination helpers, and session HTTP route implementation. Public entries are `/ui`, `/server`, `/contracts`; no root or wildcard exports. The app keeps thin route registration and typed host adapters. Existing capture processing, database executors, global transport, shared import dialogs, cleanup, race-result rendering, controls, translations, game state and authenticated RPC remain shared services. Do not move Analyse or capture engines into this feature.

Shared `SessionMeta`, `LapMeta`, recap, cleanup, result and ownership DTOs remain authoritative in `shared/racing/sessions/` and `shared/racing/results/`. Preserve their optional and nullable fields. UI host bindings must be browser-safe, explicit and typed; no app imports or untyped RPC client injection. Existing Hono-inferred RPC remains authoritative at the app adapter. Shared non-Sessions consumers must not acquire a provider requirement accidentally: move genuinely shared presentation/helpers to their proper shared owner or adapt callers explicitly.

## Existing integration boundary

HTTP behavior is defined by the existing session route implementation and shared validators, moved unchanged into package ownership. `GET /api/sessions?gameId=<GameId>` returns `SessionMeta[]`, with optional game filter, existing order and no server pagination. `GET /api/sessions/:id/recap` and `/result` require gameId and preserve recap/result DTOs and missing-data 404 behavior. Numeric IDs use shared `IdParamSchema`.

Preserve notes PATCH `{notes:string|null}` -> `{ok:true}`; favorite PATCH `{favorite:boolean}` -> `{ok:true,sessionId:number,favorite:boolean}` or 404; identity PATCH `{gameId:GameId,carId:string,trackId:string}` -> `{ok:true,sessionId:number,carId:string,trackId:string}`, with catalog validation 400 and missing/wrong-game 404. The app injects its existing catalog-identity validation through a typed server binding, not a reverse package import.

Preserve classification migration listing/status/retry, race-result reconciliation/backfill/summary/recent, reprocess and bulk-delete routes exactly, including validation, notification timing, missing-source 410, missing-session 404, stale cursor 409 and active capture partial-delete 409. Bulk delete request `{ids:number[]}` retains response `{deleted:number,sessions:number}`. Shared auth/CSRF/origin middleware stays at app registration. No authentication, endpoint, error or state-transition redesign.

UI preserves `/[game]/sessions`, `tab=others`, default Mine, legacy tab validation, page size 25, existing search/sort/selection, notes/favorites, lap actions, export, supported import formats, cleanup and responsive layout. Existing lap/import/storage endpoints are consumed through the real authenticated app adapter, not redefined or mocked in production.

### Limitations and full-mode result

Full compiled application coverage was executed and is **not green**: 255 passed, 12 failed, one flaky and six skipped. One failure was the newly strengthened pagination test: a nonmodal historical-classification notification overlapped pointer access, and the old unexercised test used the wrong previous-button name. The final scenario uses normal keyboard pagination and the existing `Prev` accessible name; it passed in the final complete Sessions run. Eleven other failures remain outside Sessions-owned specs, in Compare/Spectate layout/control assertions, Analyse telemetry and seeded chat expectations. No pre-extraction baseline was run, so these failures are not claimed to be pre-existing. No successful full-repository acceptance is claimed. [Full-mode output](../.omp/evidence/sessions-package/full-mode-e2e.log), [failure inventory](../.omp/evidence/sessions-package/full-mode-summary.json).

The optional successful standalone MoTeC `.ld` import scenario remains skipped because its `.ld` fixture is unavailable; the repository ZIP staging/configuration scenario and real binary import/export/cleanup scenarios passed. Active-capture partial bulk-delete and every original reprocess/cursor error branch were not separately fault-injected through the compiled browser entry; original handling was retained, with existing server regressions supplementing the exercised real application flows. No telemetry/auth/storage semantics or CI provisioning policy were redesigned, and no CI savings are claimed. No checkpoint was created. Owned browser/server and temporary verification scaffolding were cleaned up; local evidence remains under `.omp/evidence/sessions-package/`.
