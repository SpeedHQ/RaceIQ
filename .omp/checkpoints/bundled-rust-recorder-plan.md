# Bundle autonomous Rust recording engine with RaceIQ

## Context
Ship one bundled Rust recording engine for all six supported games: Forza Motorsport 2023, F1 2025, ACC, AC Evo, iRacing and LMU. Rust owns acquisition, source parsing, session/lap detection, sparse encoding, `.bin` writes/finalization and import processing; Bun owns uploads, database persistence, live presentation and analysis. UI uploads to Bun; Bun stages source and requests Rust import, consuming authoritative results without re-detection. Bundled transport is buffered binary stdio IPC, chosen for simplicity/low overhead; standalone/remote distribution remains deferred.

## Findings
- `apps/backend/src/runtime/boot.ts` initializes adapters/database, starts HTTP, installs shutdown, starts UDP and native supervision, then announces readiness. Actual UDP precedence includes `RACEIQ_DEV_UDP_PORT`, unlike runtime README.
- `server/telemetry/live-pipeline.ts` records before detector feed and rewrites triggering frame after recorder epoch changes. Session callback owns rotation; capture offsets point to record prefixes. Reconciliation must follow completed close.
- `server/telemetry/pipeline-ports.ts` exposes synchronous writes/offset getters, asynchronous stop. Current production default is `SparseSessionRecorderAdapter`; sparse detection currently uses `instanceof`.
- Existing sparse encoders cover RQSD generic, KNSD Kunos and LMSD LMU formats plus 128-frame checkpoint policy. User requires porting sparse encoding into Rust, preserving compatibility with TypeScript decoders; no TypeScript production sparse encoder duplicate.
- `server/session-capture/recorder.ts` lazily creates files, reserves optional 12-byte metadata header, counts only writeRecord calls, and patches count at offset 8 on close. Context bytes and boundary markers do not increase count.
- Native sources differ: Kunos recording mode bypasses parsing; iRacing/LMU recording mode still dispatches. Preserve these development modes and dump byte formats when moving acquisition into Rust.
- Release installer is Windows x64. Host builds also support macOS/Linux; Docker provides Linux UDP/import/analysis functionality. Preserve those paths, without claiming Windows shared memory works off Windows.
- Detector inventory: FM/F1/LMU use shared ordinal detector; ACC/Evo use Kunos timer-reset detector; iRacing wraps ordinal detector with delayed native lap timing. Port boundary, validity, provisional/retract and capture-window rules, not merely LapNumber changes.
- Existing RealDbAdapter inserts sessions/laps, resolves tune assignments, stores fuel/tyre metrics and triggers driver-profile notifications. Preserve those server effects when consuming Rust events. Capture completion must precede race-result reconciliation.
- Production live pipeline becomes event consumer/projector without detector or recorder. Import processing also moves to Rust, sharing parsers/detectors/writer but using isolated per-job state; TypeScript decoders may remain for historical analysis/replay, not recording/import boundary decisions.
- Bun HTTP server currently upgrades browser `/ws`; this does not influence recorder transport. Recorder uses anonymous child pipes and requires no new HTTP route.
- Import cutover must preserve existing UI-supported formats and transaction/ownership/result contracts; Bun stages original inputs, never sends Bun-decoded packets to Rust for import processing.
- Import inventory includes six-game `.bin`/`.bin.gz` and legacy dumps, RaceIQ ZIP, iRacing IBT preview/commit/cancel, LMU DuckDB with matching WAL, and MoTeC LD+LDX/ZIP for ACC/Evo. Preserve ZIP member-level partial success and deliberate duplicate creation when user repeats an import; no new global dedup policy.
- MoTeC source archives use packet-index offsets (legacy archives use fixed-record byte offsets); preserve these exceptions rather than convert every import to `.bin`. IBT staging limit is 8 GiB/30-minute TTL; MoTeC staging TTL is 15 minutes.
- User requested comparison of BOTH live capture reliability/performance and import throughput. No speedup claim is supported by current evidence. Existing `bun run bench` measures parser/pipeline microbenchmarks with null storage/DB ports, not complete imports or real capture under backend load; add end-to-end baseline/comparison evidence.

### 2. Introduce one bundled engine and binary pipe contract
Create single crate `native/recorder/Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml`, with library modules `protocol`, `engine`, `games`, `detection`, `formats`, `writer`, `imports`, `windows` and binary `raceiq-recorder`. No existing Rust engine was found. Pin Rust 1.90.0, edition 2024; dependencies serde 1/derive, serde_json 1, rmp-serde 1, uuid 1/v4, socket2 0.6, flate2 1, zip 6 with only deflate, quick-xml 0.38, duckdb 1 with bundled native library. Commit lock after resolving compatible dependencies. Windows-only windows-sys 0.61 features Foundation, System_Memory, Storage_FileSystem, System_Threading, Media_Multimedia and System_Diagnostics_ToolHelp. Use std threads, not async runtime. DuckDB compiles statically into recorder; do not attempt loading Bun's Node addon as a Rust library.

Create `server/runtime/recorder-engine.ts` with `RecorderEngine` interface and registry, export through `server/package.json`. Concrete process implementation is `apps/backend/src/runtime/recorder-client.ts`; wire parser/schema lives in `server/runtime/recorder-protocol.ts`. Backend-core does not import apps. Scripts/tests that previously called core import functions construct and register same client explicitly; no fallback TypeScript recording engine or hidden runtime compilation.

Public client API: `start(config:RecorderConfig):Promise<void>`, `request<T>(operation:RecorderOperation,input:object):Promise<T>`, `subscribe(handler:(event:RecorderEvent)=>Promise<void>):()=>void`, `shutdown(reason:RecorderShutdownReason):Promise<void>`. `RecorderShutdownReason = "signal"|"update"|"parent-eof"|"health-failure"|"startup-failure"`; forward reason in shutdown request, parent-eof supplied internally by Rust. `RecorderOperation = "configure"|"health"|"preview"|"import"|"reprocess"|"encode-capture"|"encode-lap-slices"|"forget-session"|"debug-demand"|"shutdown"`. No capture-append/start/close commands. Configure supplies resolved DATA_DIR, staging root, UDP hostname/port, feature gates, development recording game/directory, and immutable game catalog/resolver data; it does not choose session file paths or boundaries.

Both directions: `[u32 LE bodyLength][u8 opcode][u32 LE requestId][payload]`, bodyLength includes opcode/requestId. Maximum 16 MiB, minimum 5; checked lengths, fragmentation/coalescing and truncated EOF. Opcodes: HELLO=1, REQUEST=2, RESPONSE=3, LIVE_FRAME=4, EVENT=5, PROGRESS=6, STATUS=7, FATAL=8. Control payloads UTF-8 JSON; request IDs monotonically increasing nonzero u32, never reused/wrapped. Events use requestId=0; progress identifies originating request. HELLO `{protocolVersion:1,pid,platform,nativeCapture}` first message, Node platform literals `win32|darwin|linux`. RESPONSE `{ok:true,result}` or `{ok:false,error:{code,message}}`. Session/offset u64 fields in JSON are decimal strings, validated before Number conversion; counts capped at u32 and offsets/timestamps at JS safe-integer range. Unknown opcode, invalid shape/range or mismatched request ID is protocol failure.

LIVE_FRAME binary `[u64 LE sequence][u64 LE hostFrameTimeMs][MessagePack {captureId,sessionBestLapTime,packet:TelemetryPacket}]`; add `msgpackr` 1 to backend dependencies. Rust snapshot uses existing `shared/telemetry/types.ts` field names/extensions/null semantics, emits pre-pipeline-normalization telemetry; Bun reuses existing normalization exactly once. Rust detection applies equivalent recording normalization locally. Native/source parsers run in Rust, not Bun's live ingress. Telemetry has no base64 or per-frame command/ACK. EVENT JSON `{eventSequence,captureId,kind,data}` with monotonically increasing reliable-event sequence distinct from display sequence. Display snapshots may be coalesced under pressure; accepted source recording never depends on display delivery.

HELLO/startup and small control response timeout 10 seconds. Import/reprocess/encode job has no arbitrary 10-second total timeout; complete on explicit result/failure, cancel during shutdown. One stdin reader, one serialized stdout writer, one ordered recording worker per active source, one import/encode worker for service. Command responses demultiplex immediately in Bun; asynchronous DB/event processing cannot block protocol reading. Recording workers never block on stdout.

Live queue retains full-rate frames normally, bounded at 8 MiB; only on pressure replace pending display frames with latest snapshot per game. Mark sequence gaps so Bun resets continuity-dependent display trackers rather than inventing samples; recording and lap results remain authoritative/full-rate. Reliable lifecycle events are compact and queued FIFO with 4 MiB cap; Bun's asynchronous event backlog has same cap. Exhaustion finalizes captures, reports explicit delivery failure to supervisor and shuts down, never silently discards lifecycle results. Full pipe blocks output thread only. No automatic restart/reconnect/retry policy. Disk/write/protocol failure ends service with visible error; malformed imported file fails only its job. Missing mapping is normal disconnected status and retry, not fatal.

**Health supervision.** After successful configure, Bun requests `"health"` every 2 seconds with at most one outstanding probe. Health bypasses import/recording job queues; stdout gives control replies priority between complete messages without reordering lifecycle events. Response `{state:"ready"|"degraded"|"stopping",workers:[{name,state:"idle"|"running"|"stalled"|"failed",progressAgeMs,pendingBytes}],sources:[{gameId,state:"idle"|"disconnected"|"receiving",lastFrameAgeMs:number|null}],lastWriteError:string|null}`. Worker ages use Rust monotonic time; Bun tracks round-trip/last-success age with its own monotonic clock, never compares process-local monotonic timestamps.

Acquisition/control worker updates progress at least once per second even when no telemetry arrives; writer waits wake once per second to update idle progress. Import worker exposes elapsed/progress but long valid DuckDB/decompression work is not declared stalled merely for exceeding ten seconds. Acquisition/writer becomes stalled if expected idle/poll progress is older than 10 seconds; pending writer bytes without completed write for 10 seconds also marks stalled. No source frames, absent game, paused game, duplicate iRacing tick or unchanged LMU snapshot is normal source idle/disconnected, never process-offline proof. Native mapping retry sleep reports progress in interruptible one-second slices.

Probe deadline 10 seconds. Timeout sets health `"unresponsive"`; child exit/broken pipe sets `"offline"` immediately; worker stall/write error sets `"failed"` with worker/error detail. Stop new import requests, log `"[Recorder] Unhealthy: <reason>"`, publish existing notification envelope `{type:"recorder-health",state,reason}` while browser transport remains alive, then enter existing supervised shutdown/10-second termination path. No automatic restart or fallback. Bun event-loop delay over 2 seconds defers timeout verdict by one event-loop turn to drain pending IPC responses; elapsed health deadlines still use monotonic time. This avoids marking Rust dead solely because Bun's timer ran before queued stdout callback.

Expose additive `recorder:{state:"starting"|"ready"|"degraded"|"unresponsive"|"offline"|"failed"|"stopping",pid:number|null,lastSuccessfulProbeAgeMs:number|null,reason:string|null,sources}` on existing `/api/status` in `apps/backend/src/routes/settings-routes.ts`; preserve other fields and HTTP 200 response. Process heartbeat does not guarantee zero dropped frames or durable disk writes; source counters and writer errors remain separate evidence. Cancel probe timer/pending probe on intentional shutdown; expected EOF/exit is not a new failure.

**Recorder logging.** Add Rust `logger` module; no existing Rust logger exists. Bun client resolves absolute `resolveDataDir()` using `server/runtime/config/data-dir.ts` and passes private child environment `RACEIQ_RECORDER_LOG_DIR` before spawn, so startup/panic/HELLO failures can log before configure. Require configured DATA_DIR to match this resolved directory. Rust writes `<RACEIQ_RECORDER_LOG_DIR>/recorder.log`, beside Bun's `raceiq.log`; never infer cwd, use temp directory or write logs to stdout. JSON-lines records use ISO UTC `time`, string `level`, `service:"raceiq-recorder"`, `pid`, `msg` and contextual gameId/captureId/jobId/error fields. Honour existing `RACEIQ_LOG_LEVEL` values fatal/error/warn/info/debug/trace/silent, invalid => info plus warning, matching `server/runtime/logger.ts`.

Match `server/runtime/diagnostic-log-store.ts` defaults: 2 MiB active-file threshold, 25-hour retention, append on startup unless oversized; rotate to `recorder-<ISO timestamp with colon/dot replaced by hyphens>-<pid>-<counter>.log`. Close file before rename on Windows. Prune only matching recorder rotated logs; never rename/prune/write Bun raceiq logs. Use one logger writer thread, bounded 1 MiB queue, no per-frame info/debug log; diagnostic overflow counts dropped messages and reports warning when logger catches up, never blocks acquisition. Flush once per second and on orderly shutdown/fatal/panic; no fsync on each diagnostic line. Panic hook emits panic context/backtrace when enabled to log and stderr. stderr remains startup/fallback diagnostic channel; Bun drains it without copying Rust's normal file logs into raceiq.log.

Record startup/version/PID/path, source connect/disconnect, session completion, import start/result, write/protocol/health failures and update/shutdown reason. Logging IO/rotation errors follow Bun's best-effort diagnostic policy: report rate-limited stderr warning and logger degraded status, never silently switch file location or break recording solely because diagnostic logging failed. Add `logger:{state:"ready"|"degraded",error:string|null,droppedMessages:number}` to health response and `/api/status` recorder object. Overall health state degraded includes logger failure; restoring writable log clears that condition. Recorder shutdown accepts `reason:"signal"|"update"|"parent-eof"|"health-failure"|"startup-failure"` so update shutdown is distinguishable in recorder.log.

### 3. Port autonomous acquisition and game source parsing
This step and import readers can run independently once shared formats/protocol compile; do not enable new production runtime until backend consumer is ready.

Rust owns UDP sockets on all supported hosts, Windows process polling/native reader lifetimes and source-frame creation. Port process matching from `server/games/registry.ts` and adapter processNames with 2-second polling; feature-gate iRacing as boot currently does. Preserve `--record` behavior, including forced LMU source when development recording selects LMU. Port distinct development dump encoders into Rust using existing formats/path naming; Kunos dump-only mode still bypasses semantic capture, whereas current iRacing/LMU recording mode still dispatches.

UDP IPv4 hostname defaults `0.0.0.0`, best-effort receive buffer 64 MiB. Timestamp on datagram/snapshot acquisition, not Bun processing. Parse/gate FM/F1 before detection using same accepted/rejected source behavior and context retention as existing pipeline. Initial bind failure fails startup. Configure UDP port change stops/drains old source, finalizes relevant recording, binds new socket, then responds; preserve settings-route restart error semantics.

Native readers:
- Kunos: port `server/games/kunos/buffered-memory-reader.ts`, `triplet-assembler.ts`, ACC/Evo `shared-memory.ts`. ACC mappings `Local\\acpmf_physics|graphics|static`, sizes 800/1588/688; Evo `Local\\acevo_pmf_physics|graphics|static`, sizes 800/3944/256. Read physics 300 Hz, graphics 60 Hz, publish triplets 100 Hz; retain repeat packet IDs. ACC static refresh uses graphics session ID; Evo permits empty static and retains 1-second valid-static refresh/invalid retry behavior. Mapping retry 10 seconds.
- iRacing: port `packages/game-iracing/src/sdk-reader.ts`, mapping `Local\\IRSDKMemMapFileName`, 112-byte header, <=4 buffers, <=4096 variables, <=4 MiB row/session info, offsets <=64 MiB and VirtualQuery bounds. Poll 240 Hz; latest connected tick, duplicate suppression, metadata/ring-slot recheck after copy, <=3 stable-copy attempts; retry 2 seconds. Parse typed dynamic variables and YAML/session revisions in Rust; preserve schema-v3 session/delta source-frame encoding and complete session context.
- LMU: port `packages/game-lmu/src/memory-reader.ts`, mapping `LMU_Data`, 324820 bytes, 100 Hz, retry 2 seconds. Copy twice and compare exactly existing consumedRegionsMatch regions: [0,72), scoring [1632,2192+vehicleCount*584), telemetry header [128464,128468), selected telemetry row [128468+playerIndex*1888,128468+(playerIndex+1)*1888). Validate vehicle/player counts/hasVehicle, preserve session-event/elapsed-time dedupe. Emit existing V2 source frames.

RAII handle/view/timer ownership; acquire timer resolution only while native sources active. Monotonic absolute polling deadlines; stop wakes/joins threads. Acquisition queues retain <=64 MiB total source bytes; exhaust means explicit recording failure/finalization, not silent loss or unbounded allocation. Reuse scratch/buffer pools; retained frames own storage until writer/detector finish.

Port each game's parser and normalized snapshot contract, not only LapNumber:
- FM: `packages/game-fm-2023/src/index.ts` parser/projection, datagram length/race-on guards, native IDs and telemetry offsets.
- F1: `f1-state.ts`, `f1-packet-decoders.ts` and capture-formats `f1-wire.ts`; stateful session/player reset, required packet accumulation, last-lap/native invalidity, setup/status/history/classification context. A single datagram is not a complete snapshot.
- ACC/Evo: `parser.ts`, `lap-index.ts` and associated state helpers in each game package; packed source triplets from `server/games/kunos/pack-triplet.ts`, exact magic/interleaved lengths/ordinals. Evo retains player-slot, distance, validity/pit and delayed-identity state.
- iRacing: `normalizer.ts`, capture-formats variable table/source-frame/session-info; YAML-derived native identity, track length/sectors, delayed lap-time anchors and coordinate behavior.
- LMU: `normalizer.ts`, `identity.ts`, capture-formats layout/source-frame; scoring track-name/layout precedence, car/track identity, native invalidity, pit/race gates.

Generate build-time checked Rust layout/catalog data from current TypeScript schema and resolver/catalog sources; keep generated files committed with generator check, not handwritten duplicate numeric tables. Port resolver algorithms while using generated catalog data; dynamic discovered IDs are reported as metadata events to Bun, never require Bun roundtrip before recording a frame. Use stable game string IDs, not catalog-array positions as discriminators. Unknown car/track retains current sentinel/delayed backfill behavior; do not invent new identity fallback.

### 4. Port detectors and writer as one authoritative recording state machine
Add `detection/ordinal.rs`, `kunos.rs`, `iracing.rs`, `policy.rs`; source anchors `server/lap-detection/{boundaries,detector}.ts`, `server/games/kunos/{lap-detector,lap-rules}.ts`, iRacing lap-detector and LMU lap-policy. Port quality/pit/track-limit decision helpers used by these detectors (`server/lap-analysis/quality.ts`, analysis-core pit-cycle); Bun may compute derived analysis, but must not decide recording validity or boundaries.

Preserve decision order and policy constants:
- Ordinal: finalize old session before session start; identity/reset/rewind before ordinal completion; skip >1 invalid, backwards ordinal resets, final-lap completion requires native timing evidence. LMU first completed outlap/native invalidation and LastLap/peak-time fallback retain existing policy.
- Kunos: >=5s to <=2s timer reset, native LastLap freshness/peak fallback; mid-lap attachment, pit-only/tiny partial discard, short pre-timed fragment handling. ACC native validity authoritative when available; Evo track-limit/pit/quality precedence unchanged.
- iRacing: hold anomalous noncontiguous lap for confirmation, defer physical lap transition until authoritative native timing rolls, then release original boundary plus deferred frames/offsets; attach-mid-lap suppression and 10-second stale deferral without invented peak-time fallback.
- FM: >=10-second replaceable provisional incomplete snapshot on race-off; retract on resume, retain on true session change; silence alone does not finalize FM. Other detectors preserve existing 10-second stale/minimum sample rules. Import EOF follows existing incomplete/requireLaps behavior, not simulated live silence.

Recording identity `captureId` is UUID allocated by Rust; session/lap IDs in events are engine IDs, never SQLite IDs. File root is configured DATA_DIR; Rust selects `<DATA_DIR>/sessions/<game>/<existing timestamp>-<captureId>.bin` with exclusive creation. Preserve lazy creation: reserve metadata header but empty session creates no file. Header 12 bytes, count at byte 8; telemetry count excludes context/segment markers. Flush buffered writer before publishing lap event so Bun can read advertised ranges; patch header and close before RECORDING_COMPLETED. No per-frame fsync; periodic flush uses current cadence. Read/patch/close errors never emit successful completion.

Port `sparse-recorder.ts` and generic/Kunos/LMU sparse encoders into `formats/sparse.rs`: RQSD 32-byte blocks, KNSD/LMSD 64-byte blocks, exact headers/bitmap/back-distance encoding. Live checkpoint interval 128, identity/length change/context resets, delta accepted only if smaller than raw. Timestamped prefixes/segment/context bytes match framing.ts exactly. Track offsets against actual encoded prefix positions; never mirror/predict them in Bun. Preserve boundary-trigger duplication at session rollover and existing per-game source-frame-count semantics with fixture proof.

Reliable event kinds:
- `SESSION_STARTED`: gameId, source identity/ordinals/PI/type/UID, detectorVersion, rawFile path, sparse flag; may precede physical file creation.
- `SESSION_IDENTITY_UPDATED`: corrected ordinals/native IDs; same captureId.
- `LAP_RECORDED`: lapKey, lapNumber, lapTime, isValid, invalidReason, rawByteOffset/rawFrameCount, provisional flag, sessionBestLapTime and analysisRecipe.
- `LAP_RETRACTED`: lapKey of provisional row only.
- `RECORDING_COMPLETED`: final path/count/size, detectorVersion, completion reason; emitted after final incomplete/provisional decisions and close.

`analysisRecipe` preserves exact detector packet selection without retaining whole live history in Bun: `{ranges:[{offset,count}],contextOffset,appendPackets,overrides:[{offset,fields}]}`. Ranges identify ordered canonical source records for detector buffer after trimming/deferred release; appendPackets carries boundary samples not in persisted window (Kunos trigger), overrides carries authoritative iRacing timing correction. Bun decodes only these ranges for sectors/metrics/reference/curbs, not detection. For MoTeC use packet-index ranges and source-archive offsetEncoding instead of canonical byte ranges. Golden tests must prove recipes recreate original detector analysis buffers, including overlap, delayed LastLap and trimmed fragments.

### 5. Move all existing import formats onto same engine
Create Rust `imports/{capture,archive,ibt,lmu_duckdb,motec}.rs`. One isolated job parser/detector/writer state; no mutation/publication of live session, trackers or dashboard. Read staged original files with seek/streaming; never forward Bun-decoded packets into Rust. Bun keeps existing upload/token/ownership validation and HTTP response shapes.

Job request `{jobId,mode:"preview"|"import"|"reprocess",input:{path,originalName,sidecarPath?,format?},options:{gameId?,carOrdinal?,trackOrdinal?,tuneId?,captureStorage?},outputRoot}`. Paths must be absolute within configured job staging root, except explicitly authorized existing session files for reprocess/encode; no user-supplied filesystem paths exposed through HTTP. Rust returns complete result manifest in job output directory, with small RESPONSE `{jobId,resultPath}`. Manifest includes preview/format metadata, packetCount, sessions, lap descriptors/recipes, artifacts, source identity and source markers. Engine IDs map to DB IDs in Bun. Large result stays on disk, not a >16 MiB IPC message. Rust computes import results/files completely before Bun inserts rows. No live frames/lap-saved notifications from job worker.

Per-format behavior:
- BIN/gzip: magic-detected gzip, <=1 GiB decompressed capture limit, six-game sniffing across first 20 frames and existing longest-ID filename precedence only where old routes use it. Decode canonical timestamps/sparse/context/segments; legacy Kunos ACCTEST v2/v3, iRacing IRIQDMP v2, LMU LMUQDMP v1 retain complete-prefix/truncation semantics. Segment starts reset parser/detector but continue logical imported session; iRacing context initializes parser without lap sample counts. Raw-storage opt-in stays BIN-only; otherwise same sparse writer as live.
- RaceIQ ZIP v4: Rust owns bounded traversal/format detection; preserve manifest and per-member partial success, skipped/errors, nested `.motec.zip` metadata requirements and repeat-import creates-new-sessions behavior. No whole-ZIP transaction/dedup change. Reject traversal/absolute/duplicate normalized entries, multi-disk/ZIP64 and existing malformed archive conditions. Preserve limits: 512 MiB compressed, 256 entries, 512 MiB/member, 1 GiB total; MoTeC ZIP uses 32 entries/768 MiB total. Bound actual decompressed bytes, not only claimed sizes.
- IBT: port `packages/game-iracing/src/{ibt-reader,ibt-preview}.ts`; 8 GiB upload cap, 30-minute Bun token TTL, required variables, row/header/range checks, 1..1000 tick rate, <=4096 variables. Scan streaming, preserve preview identity/date/duration/candidate laps. Retain first-partial suppression and first-to-last driving range plus 5 seconds native-timing tail; encode source v3/YAML with same context. Preview makes no sessions; commit verifies staged size/content token, Rust processes original IBT, Bun registers returned identities and consumes token only on successful existing workflow. Cancel deletes staged token/input.
- DuckDB+matching WAL: port `packages/game-lmu/src/import-duckdb.ts` entirely, including preview, channel/event lookup and buildSyntheticFrame. Open private staged DB with preserved WAL beside it; disable external access/extension install/load, one DuckDB thread, 512 MiB memory limit; read-only where current DB+WAL behavior permits, otherwise recover only private copy without touching uploaded original. Quote known identifiers, never execute source-provided SQL. Preserve metadata defaults/required fields, floor-index continuous sampling, latest-event lookup, 50-Hz synthesis/native frame bytes, RecordingTime and canonical LMU identities; reject raw-storage option.
- MoTeC: port `server/motec/{ld,ldx,kunos-synthesis,kunos-packets}.ts` and ACC/Evo `motec.ts` mappings. Require LD plus LDX, exactly one pair in ZIP; Bun 15-minute staging token. Preserve linked descriptor guards, Latin-1 metadata, scaling/rate repairs, 60-Hz synthesis, beacon merge/partial rules, channel aliases/units/missing-channel capabilities/path limitations, user-selected target car/track and tune. Preserve original bytes in `.motec.zip` entries `session.ld`, `session.ldx`, `manifest.json`, version 1 packet-index encoding; historical archives without manifest retain legacy byte-offset conversion. Do not silently turn MoTeC storage into `.bin`.

Preserve route-specific zero-lap validation and response errors. Malformed file/job fails only that member/job; live recording continues. Output artifacts remain under job root until Bun persists successfully; finally delete input/temporary DB/WAL/artifacts on failed/cancelled jobs. No ordinary import progress/cancel UI added; keep existing IBT preview/cancel and route responses, engine progress available for existing orchestration.

### 6. Convert Bun into lifecycle/result consumer without duplicate detection
Refactor `server/telemetry/live-pipeline.ts` into live presentation/tracker consumer; keep normalization, calibration, sector/pit tracker, projector, debug subscription and session-laps behavior. Replace detector/recorder members with current Rust session snapshot and event callbacks. Production processPacket cannot construct `createLapDetector`, call feed or write capture bytes. Import worker has no live pipeline instance.

Add `server/telemetry/recording-events.ts` and `server/session-capture/import-results.ts` using existing DbAdapter/RealDbAdapter:
- Maintain captureId -> DB session state and lapKey -> DB lap ID in client lifetime; reliable sequence <=committed watermark is ignored, unexpected reliable gaps rejected. No persistent global import dedup/new DB identity schema needed for supervised non-reconnecting pipes.
- SESSION_STARTED inserts session once, associates Rust path/detectorVersion/sparse flag with updateSessionRawFile; reset calibration/sector/pit tracker and seed history/current laps as existing callback. IDENTITY_UPDATED calls updateSessionCarTrack and registers discovered native metadata.
- LAP_RECORDED uses Rust timing/validity/window unchanged. Recreate analysis packets with recipe through existing replay decoders; compute sectors with existing `computeLapSectors`, persist metrics/F1 setup/auto-exclusions and trace/curb effects currently in detector helpers. Resolve tune via getTuneAssignment, preserve ownership/version identity/profile notification. Update valid reference/wear curves, best lap, then emit existing lap-saved/session-laps with DB IDs.
